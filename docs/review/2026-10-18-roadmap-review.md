# laos 路线评审（2026-10-18）

> **评审对象**：laos v0.39.0（2026-09-04 首发 → 2026-10-18，**44 天 43 个 tag** = 39 个 MINOR（v0.1.0–v0.39.0）+ 4 个 PATCH（v0.15.1 / v0.26.1 / v0.28.1 / v0.35.1））。
> **本文角色**：路线评审是三类评审中唯一以**时间轴**为主轴的——需求评审回答"做什么、做到没有"，技术评审回答"怎么做的、有什么债"，路线评审回答"按什么节奏走过来的、下一步去哪、凭什么"。本文是 laos 的第一份路线评审（v0.19.0 波次未设此文档类型），作为飞书文档评审会议路线侧的依据。
> **数字口径**：版本/日期/tag 数取自 `git tag` 与 CHANGELOG.md；测试计数为 2026-10-18 实跑（主库 1180 / 隔离区 279 / 复现区 94 / 对照树 276）；未实测与未承诺处一律明写。
> **测试数 1180 的构成归属**：v0.39.0 发版时点 1158 + 1（dated 报告排除回归 d396f37）+ 6（锚点同步回归 Task #116）+ 15（当日并行 SDD 批次 check_survey 三提交）。后 22 项为未发版增量——README/decks 等介绍文件持发版时点口径 1158，ONBOARDING 事实表持门禁实跑口径 1180（口径设计见 ONBOARDING §0，详情见技术评审页眉）。

## §1 发行纪律（路线可信的地基）

| 纪律 | 内容 | 执行证据 |
|---|---|---|
| **SemVer** | 0.x 阶段：minor = 功能波次，breaking 也升 minor；纯 docs 波在 subject 尾部标 `+new-domain` 才按 MINOR | CHANGELOG 43 段 + 43 个 annotated tag，全部归档进 docs/releases/ |
| **Conventional Commits** | feat/fix/docs/chore 推导版本升降（feat→minor、fix→patch、docs/chore 不发版） | `scripts/release.py` next_version 自动推导 |
| **发版硬闸** | `release.py --apply` 先真跑测试套件，不绿拒绝发版；再同步三树 `__version__` + sync_docs 改写五类文档锚点 | 主库计数用实跑数；2026-10-18 增加 ISO 日期文件名排除（dated 现场记录不随后续发版漂移） |
| **Keep a Changelog** | 每版一段 Added/Fixed/Changed，实测数字（测试增量、精度、延迟）随段落记录 | CHANGELOG.md 全部版本段可回查 |
| **交接门禁** | `scripts/check_onboarding.py` 实跑对账：文档数字与仓库现状不符即红 | ONBOARDING.md 计数随实跑值走（当前 1180；构成归属见页眉） |
| **腐化要会失败** | 锚点由工具同步而非人记；同步面缺口以回归测试钉死（如"项测试全绿"模式 10-18 关闭） | tests/test_release.py 26 例 |

**纪律价值**：44 天 43 个版本零编号混乱、零锚点静默漂移事故（有一次被抓获并修复的千位 bug，见 §3.3）——路线图上的每个里程碑都可用 `git checkout vX.Y.Z` 精确复现，这是路线评审可进行的前提。

## §7 路线评审结论

1. **节奏判定：健康**。44 天 43 个可复现 checkpoint，测试资产 501→1180 单调增长无回退，四起腐化事件全部被自家门禁抓获并修复——节奏服务于风险控制，未牺牲质量换速度。
2. **完成度判定**：治理内核与听觉研究平台两线达成；对话控制面主体达成、闭环待 TTS。#1–#7 近期事项中，**KWS（#1）是唯一挂逾期的旧承诺**，建议定为下一波第一优先；#2/#3 是工程债清偿，成本低收益直接。
3. **v1.0 路径判定：清晰但有时延**。契约冻结（#12）的前置链 = 多 Agent 调度 → 驱动市场 → schema 版本化，按当前节奏预计还需 2–3 个功能波次；**在此之前 0.x 的 minor 即波次节奏应保持**，不为冲版本号合并验收。
4. **给路线委员会的三条建议**：①把"每 10 版一次 capstone 对账"写进发版检查单（治 L3）；②#1/#4 排期时同步立端到端延迟基线测量（治 L2）；③尽快引入第二位维护者跑一遍 ONBOARDING 上手（治 L4）——交接文档"可机器验证"的方法论需要一次真人验证。
