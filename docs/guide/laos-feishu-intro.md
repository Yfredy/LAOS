# 第一章 · 一页看懂（最小认知单元）

**laos 是什么**：Linux 内核的 Agent 治理层。不改内核一行代码，把 Linux 五十年的强制原语（namespace/cgroup/seccomp/Landlock）带给 AI Agent 的工具调用。

**三个数字**：39 个语义化版本（44 天）｜1158 项测试全绿｜17 个受治理驱动。

**一句话**：Agent 需要的不是更强的模型，是一个会说「不」的内核。

**它不是什么（同样重要）**：不是 Agent 框架（不编排 Agent 怎么思考）；不是内核模块（一行内核代码都不改）；不是 MCP 客户端（治理 MCP，不实现 MCP）。

**解决了什么**：今天的 Agent 拿着用户全部权限裸奔——一条 `rm -rf` 删光家目录，一个恶意 MCP 工具外发剪贴板。业界的防御是 System Prompt 里写「请不要做危险的事」——提示词是恳求，不是强制。laos 把能力边界、配额、审计、不可逆记账做成**派发前的制度**。

# 第二章 · 问题：Agent 拿着全部权限在裸奔

## 2.1 风险的真实形状

一个能干活的 Agent 必须能执行命令、读写文件、访问网络、操控手机。于是：

- 一条精心构造的指令可以触发 `rm -rf`
- 一个恶意/被劫持的 MCP 工具可以外发剪贴板与通知
- prompt injection 就是 Agent 世界的提权攻击：System Prompt 是「内核态」配置，注入是「用户态突破」

## 2.2 为什么现有防御不够

- **提示词防线**：文本可覆盖、可绕过，「不要做危险的事」是恳求
- **模型自觉**：模型再强也可能被网页里的隐藏文字骗过——安全边界不能建立在概率上
- **应用层 Hook**：灵活但边界弱，进程本身没有 OS 级限制

## 2.3 缺的是操作系统

能力、调度、审计、记账、隔离——这些 OS 五十年前就解决了。问题是：怎么带给 Agent 这个新负载。这就是 laos 的出发点。

# 第三章 · 全景：一张类比表 + 分层架构

## 3.1 核心类比（理解 laos 的钥匙）

| Linux | laos | 含义 |
|---|---|---|
| 进程 | Agent | 有身份、能力集、预算的受管实体 |
| 系统调用 | MCP tool call | 每一次调用都要过闸 |
| 设备驱动 | MCP Server | 17 个驱动 = 17 类受治设备 |
| 内核 | laosd 薄内核 | 只做语义层：能力/调度/审计/记账 |
| insmod | kernel.load_driver | 一行外挂任意 MCP 服务器 |

## 3.2 分层架构（自上而下）

1. **Agent 层**：业务智能体，消费 syscall 面
2. **laos 内核（laosd）**：闸门链 + 调度 + 审计 + 预算（用户态，纯标准库 51 模块）
3. **驱动子进程**：17 个 drv_*，重依赖全部隔离在这里（.venv 隔离，主库零依赖）
4. **强制层**：seccomp BPF / cgroup v2 / eBPF+CoW（内核级执行保障）
5. **Linux / MCP / 外设**：基座不变

## 3.3 定位坐标

调研结论：市面上「AgentOS」至少指 8 种东西。按强制力光谱 L0（约定层）→ L3（libOS 层），laos 落在 **L2 用户态强制层**——多数「AgentOS」是框架/壳，laos 是治理内核。

# 第四章 · 核心机制：syscall 闸门链（八环）

每一次工具调用，从「Agent 想做」到「真正执行」，过八道闸：

| 环 | 名称 | 挡住什么 |
|---|---|---|
| 1 | 能力表（caps） | 没授权的能力域直接拒 |
| 2 | task_scope | 路径前缀/App 白名单/时间窗越界即拒 |
| 3 | schema 校验 | 参数非法即拒（EINVAL 语义） |
| 4 | EDQUOT 预算 | 配额耗尽即拒 |
| 5 | FleetLedger 不可逆计价 | 先扣账后派发：发消息/删文件/花钱，风险分不够就不执行 |
| 6 | Jev 预审（opt-in） | 值不值得做的判断 |
| 7 | 确认横幅 | 高危操作人审 |
| 8 | 派发 + 全量审计 | 每笔调用留痕，可完整回放「谁在何时用掉了什么权限」 |

**实例**：Agent 想点击屏幕，但目标 App 不在白名单——第 2 环即拒，adb 命令根本不会发出，设备上什么都没发生。

**配套强制层三件套**（语义之外的内核级保障）：seccomp BPF（进程级 syscall 白名单，真拦截）、cgroup v2（驱动子进程资源上限，失控不拖垮宿主）、eBPF profiler + CoW（行为画像与分支隔离）。

# 第五章 · 设备生态：驱动即设备

## 5.1 17 个驱动全景

- **听觉**：drv_mic（录音，显式 syscall 触发）/ drv_ear（转写+评估）/ drv_rec（回放）/ drv_audio（FLASepformer 分离 + JAEC 回声消除，许可证门槛见 §7.3）
- **手机操控**：drv_screen（tap/text/dump/key）/ drv_apps / drv_notify / drv_comms / drv_battery / drv_events
- **系统与计算**：drv_fs / drv_proc / drv_sys / drv_npu（QNN 真机）/ drv_clef（密钥）/ drv_genie / drv_evolve

## 5.2 治理事实

- 所有驱动过同一套闸门：screen.* 受 App 白名单、fs.* 受路径前缀——无例外
- 外挂路线：kernel.load_driver 一行 insmod 任意 MCP 服务器；外挂默认低能力+低预算起步，审计正常再提权
- 零依赖承诺：laos/ 核心纯标准库；重依赖（torch/modelscope 等）只活在驱动子进程的独立 venv

# 第六章 · 旗舰案例：听觉四段漏斗（隐私哲学演示）

全天候听觉 Agent 怎么「随时待命又不窃听」：

1. **常驻检测**：VAD 能量门常开，不落盘只回答「有没有人声」（µW 级）
2. **触发捕获**：环形缓冲 + 唤醒词判断「是不是在叫我」
3. **即时蒸馏**：SenseVoice 本地转写 + 情绪分析，**只把文本和标签送进记忆**
4. **即焚**：原始音频按 TTL 删除（默认 6h），进记忆的是蒸馏产物不是声音本身

**四条红线**（一条都不能破）：录音只由显式 syscall 触发 ｜ `LAOS_REC=0` 全局禁录 ｜ 每次 mic 调用落审计 ｜ ASR 全本地，一个字节不出设备。

**行业印证**：STEPX Neo 智能体手机（2026-10 发布）用六麦+低功耗音频芯片把同一漏斗做进硬件；Apple Watch S12 芯片被验证同构路线——隐私账与在场账可同时算平。

# 第八章 · 生态位：印证链与差异化

## 8.1 五条外部印证（Agent 需要 OS 不是一家之言）

1. **学术**：AIOS（Mei et al., 2024「LLM Agent Operating System」）、MemGPT（LLM 即 OS）——Agent OS 已是研究命题
2. **安全**：Anthropic containment 研究——Agent 需要 OS 级隔离
3. **商业产品**：STEPX Neo / Step AOS 1.0（2026-10）——首个「大模型原生智能体手机」，把感知/记忆/调度/权限列为 OS 一等公民；其安全四点「可信/可见/可控/可逆」与 laos 的 sentinel+不可逆预算逐词同构
4. **流行论证**：《你的二十年系统功底，在 Agent 时代怎么变现？》（AI架构前哨，2026-05）——「Agent 不替代 OS，是 OS 之上的抽象」「Agent 的下半场是系统工程的比拼」
5. **协议层**：MCP=Agent 世界的 POSIX、A2A=IPC——标准化正在补上 Agent 的系统接口

## 8.2 laos 的差异化空位

上述印证止步于「Agent 运行时像 OS」——A2A 只解决通信，**没有一节讨论权限、预算、审计**。laos 做的正是这一层：治理内核。用那句行业观察说：「很多 Agent 框架在重新发明 OS 的核心机制，但他们自己可能不知道」——laos 把这些机制显式化、制度化了。
