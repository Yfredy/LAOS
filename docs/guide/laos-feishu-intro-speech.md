## §1 一页看懂（⚡ 精简版保留）

**讲什么**：60 秒建立最小认知——是什么、三个数字、不是什么。

**讲稿**：

> laos 是 Linux 内核的 Agent 治理层。注意这个定位的精确性：它不改内核一行代码，做的是把 Linux 五十年的强制原语——namespace、cgroup、seccomp、Landlock——带给 AI Agent 的工具调用。三个数字建立质感：40 天 38 个语义化版本、1146 项测试全绿、17 个受治理驱动。这句话是全项目纲领——「Agent 需要的不是更强的模型，是一个会说『不』的内核」。同样重要的是划清边界：laos 不是 Agent 框架，它不关心 Agent 怎么思考；不是内核模块，它跑在用户态；也不是 MCP 客户端——它治理 MCP，不实现 MCP。它解决的是一个具体问题：今天的 Agent 拿着用户的全部权限在裸奔，而业界的防御是把「不要做危险的事」写进提示词——提示词是恳求，不是强制。

**本章收尾**：记住一句话和三个数字，剩下八章都是这句话的展开。

## §2 问题：Agent 拿着全部权限在裸奔（⚡ 精简版保留）

**讲什么**：风险的真实形状，以及为什么三层现有防御都不够。

**讲稿**：

> 先看风险的形状。一个能干活的 Agent 必须能执行命令、读写文件、操控手机——于是一条精心构造的指令可以 `rm -rf` 删光家目录，一个被劫持的 MCP 工具可以外发你的剪贴板和通知。更根本的是防御手段的代差：提示词防线是文本，文本可以被注入——prompt injection 本质上就是用户态向内核态的提权攻击，因为 System Prompt 扮演的正是「内核态配置」的角色。模型自觉不靠谱，因为安全边界不能建立在概率上；应用层 Hook 灵活但边界弱。所以缺的不是更聪明的模型，是操作系统——能力、调度、审计、记账、隔离，这些概念五十年前就成熟了，缺的是把它们带给 Agent 的工程桥梁。这就是 laos 的出发点。

**本章收尾**：问题定义清楚了，答案的形态就浮出水面——一张类比表。

## §3 全景：类比表与分层架构（⚡ 精简版保留）

**讲什么**：用 OS 概念给 laos 建坐标系，看清五层架构和 L2 定位。

**讲稿**：

> 理解 laos 最快的方式是这张类比表：进程对应 Agent——它不是脚本，是有身份、能力集、预算的受管实体；系统调用对应 MCP tool call——每一次调用都要过闸；设备驱动对应 MCP Server；内核对应 laosd 薄内核——只做能力、调度、审计、记账四件语义的事；insmod 对应 kernel.load_driver——一行外挂任意 MCP 服务器。往下看分层：Agent 层消费 syscall 面；laos 内核 51 个模块纯标准库；17 个驱动子进程把所有重依赖隔离在自己的 venv 里，主库零依赖；再往下是强制层三件套；基座是原封不动的 Linux。在坐标上，调研发现市面上「AgentOS」至少指八种东西，按强制力光谱从约定层到 libOS 层排，laos 落在 L2 用户态强制层——多数 AgentOS 是框架和壳，laos 是治理内核。这个坐标很重要，它让你能迅速判断任何新出的 AgentOS 产品落在哪、和 laos 是什么关系。

**本章收尾**：坐标系有了，下一章钻进去看最核心的那个机制。

## §4 核心机制：闸门链八环（⚡ 精简版保留，核心章）

**讲什么**：八环逐个讲，每环挡住一种真实攻击；实例收尾。

**讲稿**：

> 这是全项目的核心机制。每一次工具调用，从 Agent 想做，到真正执行，要过八道闸。第一环能力表：没授权的能力域直接拒，对应权限位。第二环 task_scope：能力有了，但作用域限定你只能操作白名单 App、某个路径前缀、某个时间窗——越界即拒。第三环 schema 校验：参数非法即拒，这是 EINVAL 语义。第四环 EDQUOT 预算：配额耗尽即拒。第五环是最有特色的 FleetLedger 不可逆计价：先扣账、后派发——发一条消息、删一个文件、花一笔钱，都是不可逆操作，执行前先把风险分扣掉，账不够，操作就不执行。第六环 Jev 预审是可选判断层，第七章细讲。第七环确认横幅：高危操作必须人审。第八环派发加全量审计：每一次调用留痕，事后能完整回放「谁在何时用掉了什么权限」。给个实例：Agent 想点屏幕，但目标 App 不在白名单——第二环就拒了，adb 命令根本不会发出，设备上什么都没发生。八环的意义在于：安全不依赖任何单点的智能，它是一套制度。制度之外还有强制层三件套兜底——seccomp BPF 做进程级系统调用白名单，是真拦截不是约定；cgroup v2 保证驱动失控不拖垮宿主；eBPF 加写时复制做行为画像和分支隔离。语义层靠制度，执行层靠内核。

**本章收尾**：制度要管的是具体的设备——17 个驱动。

## §5 设备生态：驱动即设备

**讲讲什么**：17 个驱动的全景分类，和三条治理事实。

**讲稿**：

> 17 个驱动按器官分三类。听觉类：drv_mic 录音——显式 syscall 才触发；drv_ear 转写加评估；drv_rec 回放；drv_audio 是 FLASepformer 语音分离加 JAEC 回声消除，这个驱动的故事第七章讲，它是一个许可证红线的活案例。手机操控类：drv_screen、drv_apps、drv_notify、drv_comms、drv_battery、drv_events——这一整类回应「Agent 操作手机」的场景。系统与计算类：drv_fs、drv_proc、drv_sys 提供受控视图，drv_npu 对接端侧 NPU，drv_clef 管密钥。三条治理事实请大家记住：第一，所有驱动过同一套闸门，screen.* 受 App 白名单，fs.* 受路径前缀，没有例外；第二，外挂路线——任何 MCP 服务器可以 kernel.load_driver 一行 insmod 进来，但默认低能力低预算起步，审计正常再提权，这是新硬件的信任建立逻辑；第三，零依赖承诺——laos 核心纯标准库，torch 这类重依赖只活在驱动子进程的独立 venv 里，这是架构纪律不是洁癖。

**本章收尾**：驱动里最有讲头的是听觉管线——它是 laos 隐私哲学的完整演示。

## §6 旗舰案例：听觉四段漏斗（⚡ 精简版保留）

**讲什么**：全天候听觉与隐私红线如何同时成立；行业印证。

**讲稿**：

> 这一章是隐私哲学的完整演示。场景：一个全天候在线的听觉 Agent，怎么随时待命又不变成窃听器？答案四段漏斗。第一段常驻检测：软件 VAD 能量门常开，但不落盘、不留缓存，只回答「现在有没有人声」。第二段触发捕获：有声了，环形缓冲开始记，唤醒词判断「是不是在叫我」。第三段即时蒸馏：SenseVoice 本地转写加情绪分析，只把文本和标签送进记忆。第四段即焚：原始音频按 TTL 删除，默认 6 小时。注意本质——进记忆的是蒸馏产物，不是声音本身。配合四条红线：录音只由显式 syscall 触发；LAOS_REC=0 一票否决全局禁录；每次调用落审计；ASR 全本地。最近的两个行业印证说明这不是偏执：STEPX Neo 智能体手机用六麦阵列加低功耗音频芯片把这个漏斗做进了硬件；Apple Watch 的 S12 芯片被验证过同构路线。不同的是，laos 在没有专用芯片的 Android 环境里，用软件把同一套账算平了。

**本章收尾**：这套系统的质量怎么保证？看测试、复现和调研三件套。

## §7 质量与文化

**讲什么**：测试与版本纪律、复现隔离区、调研家底、一个诚实教训。

**讲稿**：

> 质量这章讲四件事。第一，测试与版本：1146 项测试全绿——这是 10 月 18 日实跑的数字，不是宣传口径；TDD 先红后绿；SemVer 加 Keep a Changelog，一个完整需求波次等于一次 MINOR，38 个版本全部有 tag 和归档，发版自动化保证测试不绿就发不了版。第二，复现隔离区：论文不是引用，是复现——BS.1770-4 响度计量在 R128 校准点做到 −23.00 LUFS 上下 0.1 的误差；FxLMS 主动降噪超过 20 分贝；说话人朝向全管线复现。方法论是四句：TDD、零新依赖、论文数字不作断言、偏差全记档——跑不动的等比缩距并写明。第三，调研家底：双会议 19,792 篇论文全量语料，3,724 个开源仓库普查，116 份调研文档，每条落成已落地、推荐、不做三态。这里有一个红线案例值得讲：FLASepformer 和 JAEC 两个音频模型能力其实匹配，但许可证是 CC BY-NC 禁商用——我们把它记为驱动侧可选位，不进默认链路。第四，一个诚实教训，它比任何数字都能说明项目气质：Jev 判断层的 rule 后端实测校准精度只有 0.519，高置信桶错误率 33%——越自信越离谱。所以立了规矩：自动门禁禁配 rule 后端，校准先于自动化。宁可记难看的数字，不要漂亮的故事。

**本章收尾**：这样的项目在行业里处于什么位置？

## §8 生态位：印证链与差异化

**讲什么**：五条外部印证 + laos 的差异化空位。

**讲稿**：

> 「Agent 需要操作系统」不是 laos 一家之言，我们归档了五条印证链。学术线：AIOS 论文的标题就是 LLM Agent Operating System，MemGPT 把 LLM 当操作系统设计。安全线：Anthropic 的 containment 研究——Agent 需要 OS 级隔离。商业线：STEPX Neo，刚发布的全球首款大模型原生智能体手机，把感知、记忆、调度、权限列为 OS 的一等公民——它的安全四点「可信、可见、可控、可逆」和 laos 的 sentinel 加不可逆预算几乎逐词同构，这是 AgentOS 命题从论文玩具变成商业产品的标志。流行论证线：那篇《你的二十年系统功底在 Agent 时代怎么变现》——「Agent 不替代 OS，是 OS 之上的抽象」，「Agent 的下半场是系统工程的比拼」。协议线：MCP 是 Agent 世界的 POSIX，A2A 是 IPC——标准化正在补上系统接口。但请注意这条印证链的共同边界：它们都止步于「Agent 运行时像 OS」——A2A 只解决通信，没有任何一条讨论 Agent 之间的权限、预算、审计。这正是 laos 的差异化空位。用文章里那句行业观察收尾：很多 Agent 框架在重新发明 OS 的核心机制，但他们自己可能不知道——laos 做的事，就是把这些机制显式化、制度化。

**本章收尾**：位置讲完了，最后是你怎么参与。

## §9 路线图与参与方式（⚡ 精简版保留）

**讲什么**：短中长期路线 + 具体参与入口。

**讲稿**：

> 路线图分三段。近期：drv_screen 的多轮真机验收、外挂驱动的概念验证——用 mobile-mcp 做 PoC，前提是遥测关闭——以及论文复现持续。中期：多 Agent 并发调度，这是进程组语义的 Agent 版；驱动市场，把第三方 MCP 的治理接入标准化。远期：端侧完整语音 Agent 参考机，laosd 加听觉栈加全双工闭环；持久记忆层——注意这需要 PIPL 单独同意门前置，方向上是给记忆加文件系统语义：时间戳、配额、垃圾回收。参与方式很直接：仓库在 GitHub 公开，Yfredy/LAOS；上手读 ONBOARDING.md——这份文档有腐化校验门禁，里面的数字和仓库实跑对不上会直接报错，保证你读到的是真话；贡献入口建议从「把一个 MCP 服务器包装成受闸门治理的驱动」开始，这是理解全栈最短的路径。最后用项目里我最喜欢的一句收尾：Linux 内核从来不追求零 bug，它追求的是每个 bug 的爆炸半径可控——laos 把这套哲学带给了 Agent。变的是工具，不变的是思维方式。

**本章收尾**：感谢阅读，欢迎来 GitHub 提 issue。
