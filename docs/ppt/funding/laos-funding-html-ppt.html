PROBLEM · THREE PILLARS

工具调用没有 syscall 层，三笔账都在失控。

① 失控成本

一次 tool call 就是一次不可逆操作：误删文件、超额扣费、并发写坏状态。

LangChain / MCP host 在应用层 try-catch——挡不住。

场景："帮我把日志清一下" —— 十分钟后家目录没了。

② 合规黑洞

EU AI Act 已生效；PIPL 把声纹列为敏感个人信息。

企业上 Agent，缺一层可审计的证据链。

场景：采购问"Agent 调过谁的数据、何时调的" —— 拿不出证据。

③ 端侧碎片

手机 / 耳机的麦克风、屏幕、通知、NPU 各自为 SDK，没有统一隐私闸。

Agent 接入每一件设备，都要重写一遍。

场景：换一款耳机，听觉链路全部重写。

三个问题指向同一个缺口：缺的不是更聪明的模型，是一层操作系统。

laos · 创新融资项目介绍 · 2026-10
三根痛点柱，对应三笔失控的账。第一，成本：一次工具调用就是一次不可逆操作，误删文件、超额扣费、并发写坏状态，都是真实发生的；LangChain 这些框架在应用层 try-catch，挡不住。第二，合规：EU AI Act 已经生效，PIPL 把声纹列为敏感个人信息，企业拿不出证据链就不敢上 Agent。第三，端侧：麦克风、屏幕、通知、NPU 每家一套 SDK，接一件设备重写一遍。三个问题指向同一个缺口——缺一层操作系统。过渡：那为什么这层 OS 偏偏现在才做得起来？

一句话定位：laos 是Linux 内核的用户态治理延伸。看这条链路：Agent 的每次工具调用，先过内核的闸门链、调度、分支和记忆，再到十五个驱动子进程，最后才落到 Linux、MCP 和外设——真实世界永远在内核之后。三件内核语义请记住：工具调用就是系统调用，MCP Server 就是设备驱动，能力表就是权限位。还有一个硬承诺：内核纯 Python 标准库、零依赖，低端安卓和边缘盒子都能跑。这不是规划稿，是已经跑起来的 v0.12.0。过渡：壁垒在哪里？接下来三页。

laos · 创新融资项目介绍 · 2026-10
第一道壁垒，也是全项目最硬的一页。八环闸门：能力表、任务范围、schema 校验、预算、不可逆计价、预审、确认横幅、审计。越界在第二环就被拒，驱动根本不被触达——这是和应用层 guardrail 的本质区别：别人是"建议"，laos 是"强制"。重点讲金框那环 FleetLedger：先扣账后派发，操作前风险已定价，事后不可抵赖——这是操作系统记账的方式，不是安全软件扫描的方式。如果投资人问"这算不算安全功能"，答：不是杀毒，是记账加强制，是 OS 对待进程的方式。
