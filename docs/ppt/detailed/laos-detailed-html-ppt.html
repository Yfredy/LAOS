§ B2 · SYSCALL GATE CHAIN · 全片核心

每一次 tool call，过八环闸门。拒绝发生在派发之前。

agent → ①能力表 → ②task_scope → ③schema → ④EDQUOT → ⑤FleetLedger → ⑥Jev预审 → ⑦确认横幅 → ⑧派发+审计

1

能力表 caps

如 screen.*——未授权能力，第一环即拒

2

task_scope

路径前缀 / pkg: 应用白名单 / time: 时间窗

3

schema 校验

参数非法即拒——EINVAL 语义

4

EDQUOT 预算

配额耗尽即拒，不欠账

5

FleetLedger 计价

不可逆操作先扣账后派发，风险分扣减

6

Jev 预审

opt-in 判断层：值不值得做（B4 展开）

7

确认横幅

高危操作人审——最后一道是人

8

派发 + 审计

每笔 tool call 留痕，事后可回放

例：screen.tap 越过 pkg: 白名单 → 第 2 环即拒，不触 adb——拒绝发生在任何真实副作用之前。
github.com/Yfredy/LAOS

全片最核心的一页，按编号顺序走：一能力表、二作用域、三 schema、四预算、五计价、六判断、七人审、八派发加审计。

前四环是"能不能"，第五环 FleetLedger 是"值不值"——不可逆操作先扣账后派发，风险分扣减，记账发生在副作用之前，这是和普通审计日志的本质区别。

底下这个例子请念出来：screen.tap 越过 pkg 白名单，第二环就拒了，adb 根本不会被触到——拒绝永远发生在真实副作用之前。

§ B3 · BRANCH & MEMORY · 分支与内存模型

类 git 语义的 Agent 上下文：分支试错，合并回主线。

分支树

Agent 可以在分支上试错——失败的就丢弃，上下文不被污染。

写时复制上下文

CoW：分支只复制要写的部分，试错的内存代价接近零。

MemoryStore + 日记层

diary / journal 两层日记；记忆闸门只记实际发生的交互。

语义对照：git 的 branch / merge / CoW，搬进 Agent 上下文管理——记忆不写想象，只写事实。
github.com/Yfredy/LAOS

Agent 最贵的资源是上下文窗口。laos 的答案是把 git 语义搬进来：branch.py 开分支试错，cow.py 写时复制让试错几乎免费，成了再合并回主线。

右下这条是和 C3 呼应的伏笔：记忆闸门只记实际发生的交互——被丢弃的分支、没送达的响应，都不进记忆。

一句话总结：试错可以大胆，因为代价被 CoW 压到接近零；记忆可以信任，因为它只写事实。

§ C3 · FULL-DUPLEX TURN-TAKING · 全双工轮转三件套

什么时候说话，是工程问题不是礼貌问题。

事件时间线 → 四能力分解

响应延迟 · 打断响应 · 重叠率 · 抢话计数 —— Duplex-MPE 的四维评测框架

speak / hold / stop 三态

三闸防过早响应：min-speech 200ms · tail-silence 500ms · min-hold 250ms

打断即作废

未送达帧丢弃 · 只记已送达（记忆不写想象）· interject 插队帧——慢系统结果无缝织入

来源论文：Duplex-MPE · SALMONN-duo · Context Spanning（2026-09 周报波）

三态 × 三闸 × 四测——轮转策略全部可测、可调、可回归。

github.com/Yfredy/LAOS

全双工三件套按层讲：duplex 管度量，turnpolicy 管策略，turnbuf 管缓冲。

duplex 把对话画成事件时间线，导出响应延迟、打断响应、重叠率、抢话计数四个数——这是 Duplex-MPE 的能力分解，轮转好不好不再靠感觉。

turnpolicy 三态 speak、hold、stop，配三道时间闸：两百毫秒、五百毫秒、二百五十毫秒，专防过早响应抢话。

turnbuf 最妙的一条：打断即作废，只记已送达——和 B3 呼应，记忆永远不写想象；interject 让慢系统的结果插队织入。

单独同意 required——所以 ASR 全本地、只留事件不留波形（C4）。
