A2 · 命题P03 / 19

不改一行内核代码，把 Linux 变成 Agent 的操作系统

复用四件内核遗产

namespace隔离——每个 Agent 一间机房
cgroup配额——CPU/内存有上限
seccomp-BPF系统调用过滤——白名单外的 syscall 直接拒绝
landlock文件沙箱——路径前缀外的文件不可见

词表映射

MCP Server= 设备驱动
tool call= 系统调用
laosd= 薄内核
能力表= 权限位
关键判断：Agent 时代的「内核」不是重写调度器，而是给工具调用装上 syscall 语义——能力、预算、审计、判断，四件事在派发之前完成。

B1 · 总体架构P05 / 19

四层栈，内核零依赖，重依赖只活在驱动子进程

L4Agent（brain / agent）——想做什么

L1Linux / MCP / 外设
laos/ 目录 0 第三方依赖 三棵树：主库 · AlwaysOnRec 隔离区 · Repro 复现区
B · 内核组kernel.py → drivers → world
架构一页：值得强调的是两条纪律——内核纯 stdlib（意味着任何有 Python 的低端设备都能跑），以及驱动全部子进程化（重依赖与崩溃都被隔离在内核之外）。三棵树是研发治理：主线、隔离实验、论文复现互不污染。

B3 · 分支与内存模型P07 / 19

Agent 的上下文，值得 git 级别的待遇

main ──┬── agent/a · 试错分支
         └── agent/b · CoW 上下文
branch.py 分支树 + cow.py 写时复制：Agent 在分支上试错，合并回主线；上下文复制是懒的，只在写入时发生。

MemoryStore + diary/journal

记忆闸门：只记实际发生的交互，不记想象的交互；diary/journal 把一天的事件流沉淀成可回放的日记。
commit 水位语义：TurnBuffer 只把「已送达」的内容写进记忆——打断作废的尾部永远不进历史。
B · 内核组branch · cow · memory
两件事：一是分支/CoW，让 Agent 敢试错——错了丢分支，不污染主线；二是记忆闸门，只记实际送达的交互。右下那句是 v0.10.0 从 Pipecat 复现里拿来的语义，打断即作废。
