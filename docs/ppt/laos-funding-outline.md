## 页面清单（15 页）

**P1 封面**
- laos —— Linux 内核的 Agent 治理层：基座不变，治理延伸
- 立场声明（全篇叙事基准）：**基座与核心是 Linux 内核**；Agent 只是内核之上的新负载（与进程同类）；laos 在用户态把内核的治理——syscall 语义、能力、预算、审计——延伸到这个新负载。**不是给 Agent 外挂一个操作系统**
- 创新融资 · 项目介绍 · 2026-10
- 角标：v0.12.0 · 30 天 12 个版本 · 765 测试

**P2 一页看懂（If they remember one slide）**
- 问题：Agent 直接拿工具，没有"系统调用"层——无预算、无审计、无回滚、无合规
- 方案：laos = Linux 内核的用户态治理延伸：8 环 syscall 闸门链（能力→范围→校验→预算→计价→预审→确认→审计）
- 进展：开源 v0.21.0 · 15 个设备驱动 · 端侧听觉栈全自研纯 stdlib · 19,792 篇论文语料
- 一句话：模型负责想，laos 负责说"不"

**P3 痛点三柱**
- ① 失控成本：一次 tool call 就是一次不可逆操作——误删文件、超额扣费、并发写坏状态；现有框架（LangChain/MCP host 等）在应用层 try-catch，挡不住
- ② 合规黑洞：EU AI Act 已生效、PIPL 把声纹列为敏感个人信息——企业上 Agent 缺一层可审计的证据链
- ③ 端侧碎片：手机/耳机的麦克风、屏幕、通知、NPU 各自为 SDK，Agent 接入每一件都要重写一遍，且没有统一隐私闸
- 每柱给一个具体场景（一行）

**P4 为什么是现在（三浪叠加）**
- 浪 1：MCP 成为事实标准（2026-07-28 规范更新：Tasks/Elicitation/MRTR）——工具调用接口统一，治理层有了统一切入点
- 浪 2：Agent 从聊天走向执行（企业开始让 Agent 动真实系统）——"能干活"到"敢让它干活"之间差的正是内核治理的延伸
- 浪 3：监管落地窗口（EU AI Act 分阶段生效 / 国内生成式算法备案）——合规是预算充足的用户

**P5 产品：laos 是什么**
- 一张架构图：Agent ↔ laos 内核（闸门链+调度+分支+记忆）↔ 15 个驱动子进程 ↔ Linux/MCP/外设
- 三件内核语义：tool call=系统调用 · MCP Server=设备驱动 · 能力表=权限位
- 零依赖承诺：内核纯 Python stdlib——可进任何低端安卓/边缘盒子的 Python 环境

**P6 核心壁垒一：8 环闸门链**
- 图示 8 环：能力表 → task_scope → schema → EDQUOT 预算 → FleetLedger 不可逆计价 → Jev 预审 → 确认横幅 → 审计
- 不可逆账本：先扣账后派发，操作前风险已定价，事后不可抵赖
- 对照：现有方案（应用层 guardrail/策略文件）是"建议"，laos 是"强制"——越界在第 2 环即拒，驱动根本不被触达

**P7 核心壁垒二：端侧听觉栈（全自研、纯 stdlib）**
- 六层：VAD → BS.1770-4 响度（校准锚点 −23.00 LUFS ±0.1）→ Goertzel 双耳 ILD/IPD → 麦克风几何 MPE → FOA 编解码 → ShoNet 声源定位复现
- 全双工三件套：时序度量 / speak-hold-stop 轮转策略 / 打断即作废轮缓冲
- 为什么值钱：语音是 Agent 最自然入口，端侧=隐私合规的唯一安全区——而市面方案全部依赖云端大模型

**P8 核心壁垒三：合规先发**
- 已完成的法条功课：EU AI Act 禁令清单 / PIPL 声纹单独同意 / 录音触发四红线（显式 syscall、LAOS_REC=0、全量审计、ASR 本地）
- 拒绝清单实证：对标开源产品的七个越界文件逐行分析后一行不抄
- 卖点：企业采购 Agent 基础设施时，"可审计"是入场券，不是加分项

**P9 竞争格局**
- 坐标系：L0 约定层（框架/壳）→ L3 libOS 层；laos 在 L2 用户态强制层
- 四象限：框架派（LangGraph 等，无强制）/ 治理派（策略引擎，不在执行路径上）/ 端侧派（各家 SDK，无 OS 语义）/ laos（唯一：执行路径上的强制 + 端侧驱动 + 审计账本）
- 学术对照：Rutgers AIOS 是调度优先，与 laos 互补不互竞（调研结论）
