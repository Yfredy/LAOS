P2 · 一页看懂02 / 16

工具调用没有 syscall 层，这就是全部问题

问题

Agent 直接拿工具——无预算、无审计、无回滚、无合规证据链。

方案

laos = Linux 内核的用户态治理延伸：八环闸门链，能力→范围→校验→预算→计价→预审→确认→审计。

P3 · 痛点三柱03 / 16

Agent 敢不敢用，卡在三件事上

壹

失控成本

一次 tool call 就是一次不可逆操作：误删文件、超额扣费、并发写坏状态。现有框架在应用层 try-catch，挡不住。
场景：Agent「整理磁盘」删掉生产库——没人拦得住。
贰

合规黑洞

EU AI Act 已生效，PIPL 把声纹列为敏感个人信息。企业上 Agent 缺一层可审计的证据链。
场景：审计问「这次删除是谁批准的」——答不出。
叁

端侧碎片

手机/耳机的麦克风、屏幕、通知、NPU 各自为 SDK，Agent 接每一件都要重写一遍，且没有统一隐私闸。
场景：同一段录音逻辑，五个设备写五遍。
§1 问题与时机壹贰叁 —— 中文账本防涂改数字
三柱用壹贰叁——中文账本的防涂改写法，呼应我们的账本母题。每柱一个真实场景。注意第三柱：端侧碎片不只是效率问题，是没有隐私闸的问题——这正是我们听觉栈的机会。
P4 · 为什么是现在04 / 16

三浪叠加，窗口就在这 18 个月

浪一 MCP 成为事实标准（2026-07-28 规范更新：Tasks / Elicitation / MRTR）——工具调用接口统一，治理层第一次有了统一切入点。
浪二 Agent 从聊天走向执行——企业开始让 Agent 动真实系统；「能干活」到「敢让它干活」之间，差的正是内核治理的延伸。
浪三 监管落地窗口——EU AI Act 分阶段生效、国内生成式算法备案；合规是预算充足的用户。
§1 问题与时机接口统一 × 采用爆发 × 监管落地
为什么是现在而不是两年前/两年后：两年前没有统一工具协议，治理层没处挂；两年后标准位被占完。MCP 2026 年 7 月底那次规范更新把 Tasks 和 Elicitation 定下来，切入点刚刚出现。

§2 产品与壁垒六层全部纯 stdlib 自研
第二个壁垒是听觉栈。每层都有锚点数字——响度校准到广播标准，几何编码与谷歌官方实现逐位一致。重点讲右下角：所有竞品语音方案都把音频送云端，而 PIPL 把声纹定为敏感个人信息——端侧是唯一安全区，我们恰好整套都在端侧。

P11 · 商业模式11 / 16

开源内核建标准，卖的是「敢用」

① 治理中间件

企业私有化：闸门链 + FleetLedger 打包进企业 MCP 网关。
License + SLA

② 审计报表 SaaS

FleetLedger 数据 → 合规证据链导出。
按 Agent 数量订阅

③ 端侧语音 SDK

零依赖听觉栈 + 全双工轮转授权设备厂。
OEM 按量授权
定价哲学：内核永远开源建标准；收费层是强制执行与证据链——企业为「敢用」付费，不为功能清单付费。
§4 商业与融资三条线一个账本底座
三条收入线共享同一个底座：FleetLedger 账本。线一私有化中间件最快变现；线二 SaaS 是经常性收入；线三 SDK 是长尾。被问"开源怎么收钱"：收的是强制执行和证据链，不是功能——功能可以抄，账本的可信度抄不走。
