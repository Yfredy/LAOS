0. 关键事实速查

一句话不改内核：namespace/cgroup/seccomp 做强制层，laosd 薄内核做语义层，MCP Server 当设备驱动，tool call 当系统调用

1. 系统架构与路线

1.1 三层结构

层角色laos 中的实现传统 OS 对应
语义层进程表、能力表、预算、审计、路由laos/kernel.py 薄内核（PCB + syscall 网关）内核核心
强制层真正的隔离与资源上限Linux namespace / cgroup v2 / seccomp BPF / PathJail硬件与内核强制
驱动层把文件/进程/系统信息封装成 tooldrv_fs / drv_proc / drv_sys（独立 MCP 子进程）设备驱动 + /dev
调度LLM 时间片与可靠性预算AgentScheduler（token/err 双预算轮转）CPU 调度器
内存上下文分页与换出ContextManager（窗口 + 摘要压缩 + swap）虚拟内存
探索fork / explore / commitBranchContext + hardlink COW（first-commit-wins）fork / COW
审计事后追责与回放AuditLog(JSONL+seq) + laosctl 离线回放 + AgentProfstrace + auditd

1.2 一次 syscall 的完整闸门链（顺序即语义）

kernel.syscall(pid, tool, args)
 ├─ PCB 存在?            否 → ESRCH
 ├─ 进程已 killed?        是 → EACCES
 ├─ 查 syscall 表         （MCP 表 → 内建表，都 miss → ENOSYS）
 ├─ 能力检查（caps ∪ 未过期委托）          → EPERM
 ├─ task_scope 路径前缀收窄（normpath 后匹配）→ EACCES: outside task scope
 ├─ 参数 schema 校验                       → EINVAL
 ├─ 次数预算 EDQUOT        ← 必须在风险闸门之前：注定被拒的调用不许消耗风险额度
 ├─ 不可逆风险闸门：车队账本 → agent risk_cap → risk=="high" 需人类 confirm
 └─ 派发：内建同步 / MCP 走 to_thread + per-driver 锁
       └─ 唯一收口 scheduler.note_outcome(pid, ok)   （内核 _deny 不算 agent 失败）

路线代表优点代价

5. 内核契约速查

5.1 PCB（进程控制块）字段

pid / name / caps / state(ready|running|blocked|zombie|killed) / parent
created_at / ctx(ContextManager) / branch / budget(syscall 次数)
risk_cap(per-agent 风险帽) / task_scope(路径前缀白名单)
stats{syscalls, denied, tokens, risk}
快照防坑to_dict 先 replace(self, ctx=None) 再 asdict——ctx 是活对象，demo 线程还在追加；ps() 先对 procs.values() 取 list 快照，否则 HTTP 观测线程会撞 "dictionary changed size during iteration"。

5.2 errno 语义表（字符串前缀，可透传、可归因）

errno产生层含义控制面归因
ESRCH内核pid 不存在 / 被调度器挂起内核拒绝（denied）
ENOSYS内核syscall 表里没有这个 tool内核拒绝
EPERM内核 / seccomp能力表未授权 / 过滤器拦截内核拒绝
EACCES内核 / PathJail越出 task_scope / 越出 jail / 风险预算不足内核拒绝
EDQUOT内核syscall 次数预算耗尽内核拒绝
EDENIED驱动危险命令被驱动黑名单拦下 / elicitation 拒绝驱动拒绝（failed）
ENOENT / EISDIR / EFBIG / ENOTDIR驱动文件系统常规错误驱动失败
ETIMEDOUT驱动MCP Tasks 轮询超时驱动失败
ENOBUFS / EMSGSIZE内核 IPC信箱满 16 条 / 消息超 4096 字符背压
核心约定驱动抛出的 errno 原样透传，绝不包一层 EIO——上层必须能区分「被拒绝」和「驱动崩溃」。laosctl ps 就是靠 errno 前缀把 rejected 拆成 denied（内核拦的）与 failed（驱动拒的）两类。

6. 核心流程详解

6.1 laosd 七幕引导（bin/laosd.py）

幕内容关键点
1 内核启动AgentKernel(workdir) + load_driver×3打印隔离能力报告与 9 条 syscall 表
2 分支 forkmain → exp-A / exp-Bhardlink 只复制目录项，数据块共享
3 起进程ops-agent（全权）+ guest-agent（仅 sys.* + task_scope=/exp-A/）visible_tools 按 caps 裁剪后才给 LLM
4 ReAct每步 drain 通告 → think → syscall → 结果回灌errno 原文进上下文（[error] EPERM: ...）
4.5 IPCmsg.send/recv + sys.delegate（TTL=1 次后 EPERM）演示「委托-过期-撤销」闭环
5 commitdiff → 应用 → first-commit-wins 作废 exp-B → 广播 stalediff 必须在 commit 前取，否则两边一致 diff 变空
6/7 报告syscall 数、拒绝分类、风险账本、span 评分、调度快照被拒调用按「内核能力表 / task_scope / 驱动」三层归因打印

6.2 diff-based commit（branch.py）

def _diff_files(self):
    base_files, ws_files = snapshot(self.base), snapshot(self.workspace)  # rglob 文件集
    if sa.st_ino and sa.st_dev == sb.st_dev and sa.st_ino == sb.st_ino:
        return True                    # inode 快路径：CoW 保证共享 inode 从不原地改写
    return a.read_bytes() == b.read_bytes()
# commit(): 先算 diff → 逐项 cow_write 回父分支（绝不 copy2 原地截断共享 inode）
#           → 遍历 parent.children 把其他 exploring 兄弟置 INVALIDATED
为什么不用 journalAgent 的写操作发生在 MCP 驱动进程里，分支层看不见——第一版靠 journal 记账，结果提交了个空。不信任记账，以快照 diff 为准（语义等同 overlayfs upper/lower 合并）。

6.3 CoW 原语（cow.py）—— 无条件 temp+replace

tmp = p.with_name(f".{p.name}.cow-{os.getpid()}-{threading.get_ident()}.tmp")
tmp.write_bytes(raw); os.replace(tmp, p)     # 原子目录项替换，旧 inode 上的兄弟链接不受影响

关键注释：永远无条件走 temp+replace，不判断 st_nlink 再决定写法——「先判断后写入」在 fork 并发下是 TOCTOU 竞态。cow_append 是读旧+整体替换而非真 append（append 到共享 inode 会污染兄弟分支）。

6.4 强制层封装与 fail-closed（sandbox.py / seccomp.py）

  • 包装顺序不可颠倒：unshare 在最外层 → seccomp shim 在 namespace 里 → 真命令。过滤器 deny 了 unshare(2)，必须等它干完活再装。
  • bootstrap shim：python -c "组装; install(prog); execvp(...)"，组装失败必须 sys.exit(1) —— 绝不 exec 一个无过滤器的裸驱动（fail-closed）。
  • deny 用 RET_ERRNO|EPERM 而非 kill：调用方拿到可观察的 EPERM，而不是进程凭空消失。
  • 黑名单不碰 CPython 命脉（clone/futex/execve 绝不在列），并封死 open_tree/move_mount 等可绕过 legacy mount 的新挂载 API。安装前先 PR_SET_NO_NEW_PRIVS。
  • 能力探测降级：IsolationReport(level, backend, reasons) —— 非 Linux=off，有 unshare 非 root=partial，都没有=none（仅能力表）。降级原因写进审计，不静默。
  • cgroup 纳管技巧：attach 到 unshare --fork 的真实子进程，靠进程树继承罩住 proc.exec 的孙进程，无需逐个 attach。

6.5 人类在环：confirm 闸门（laosweb.py）

web_confirm(op):  _pending[cid] = {op, event, answer}; entry["event"].wait(60)
UI: 红色横幅渲染 pending_confirm → 点允许/拒绝 → POST /api/confirm → event.set()
超时 = 拒绝。LAOS_CONFIRM=auto-yes 秒答 True（跳横幅、照常计费 risk）。

接线：MCP 驱动的 elicitation/create 请求 → 内核 client.on_server_request → kernel.confirm → Web 横幅。红线：task 线程内禁止 elicit（会与主循环抢 stdin）。

6.6 fail-safe 重启（laosweb.py）

  1. 先校验 risk_budget > reserve，否则 400 —— 避免新内核连 operator 都 spawn 不进；
  2. _restart_lock.acquire(blocking=False) 防并发双击 → 409；
  3. 新栈完全就绪才 cutover（set_kernel + 起 demo），之后才 old.shutdown() + _deny_all_pending()（冻在确认关的旧线程按「拒绝」苏醒退场）；
  4. demo 线程带代号（_demo_gen），旧线程不得抢新 demo 的运行徽标。

6.7 stale context 观察簿（context.py）

fs.read 成功     → pcb.ctx.observe(path, sha256(result)[:16])
fs.write/append  → 遍历所有其他 agent 调 invalidate(path)
分支 commit      → on_branch_committed() 虚拟化路径后全量广播（未观察过的 no-op）
agent 每步开头   → drain_notices() → ctx.notice("STALE: ... 请重新 fs.read")

两个细节：notice 用 user 角色注入（append("system") 会替换系统提示）；drain 一次性取走即清，避免刷屏。

12. 与 DSHA 的共同之处

13. DSHA 可借鉴清单（按优先级，标注落点）

P0统一审计流 + seq 单调号 + 离线回放控制面

缺口：DSHA 的可观测性 = Logcat + 应用内自检（selftest.py 23 项）+ 零散日志，没有跨进程的统一事件总线，出问题时无法按时间线复盘「agent 做了什么、被谁拦下」。
抄法：容器内所有关键动作（dsh 启停、桥命令、安装六步、插件操作、备份）追加写一条 JSONL 到 /sdcard 或私有目录的 audit.jsonl，字段对齐 laos：{t, event, actor, tool, args, ok, ms, result, seq}；seq 在 append 前盖章。再写一个 ~200 行的 dsha-ctl.py（放容器 PATH）提供 ps/trace/denied/top——纯读文件，不需要在线内核。laos 证明这整套东西 180 行就够。
落点：HarnessService / HttpShellService / InstallPipeline / BackupManager 的关键分支各加一行 append；对应 AGENTS.md 回填清单 #3。

P0拒绝归因约定（errno 前缀分层透传）

缺口：DangerShellGuard.isDangerous 只返回布尔；桥命令被拦、proot 失败、驱动崩溃在日志里不可区分。
抄法：约定统一前缀——EPERM（权限/确认拒绝）、EDENIED（危险命令拦截）、EDQUOT（预算耗尽）、EIO（进程失败），原样透传给 dsh 上下文与审计，绝不包壳。这样 dsha-ctl denied 才能把「被谁拒的」分类统计——这是 laosctl ps 里 denied vs failed 的唯一依据。
落点：HttpShellService 拦截分支、DangerShellGuard、bridge 问答协议。

P1不可逆操作风险账本（按工具定价）

缺口：DSHA 有确认弹窗但没有累积记账——一个会话里 agent 可以反复申请危险操作，人疲劳之后会无脑点允许（DangerShellGuard 注释自己预言了这个失败模式）。
抄法：给桥会话加 risk 预算：rm -rf=3 分、pm uninstall=3、chmod 000=2、普通确认=1；per-session risk_cap 超限 → 直接 EPERM 不再弹窗（强迫重开会话）；全局账本剩余 < 保留水位 → 新 dsh 会话拒绝启动（spawn 准入）。laos 的 risk.py 只有 50 行，两级记账（per-agent / per-tool 直方图）+ attempt-based 计费即可。
落点：ConfigStore 加两个键；HttpShellService 确认分支后记账。

P1task_scope：能力随任务意图收窄

缺口：dsh 会话一旦起来就拥有整个 rootfs 视图；「能力说能写文件，任务没说能写哪些文件」。
抄法：spawn dsh 时可带任务路径白名单，映射成 proot 额外的只读/拒绝绑定（-b path:ro 或 blacklisted 路径）——ProotBootstrap/ContainerRuntime 已有 BINDS 组装点，落地成本最低。内核侧再加一道 normpath 前缀校验（laos 的收边写法：分隔符收边，/workspace/host 不得匹配 /workspace/hosts），双层防御。
落点：ContainerRuntime（BINDS 清单）+ RuntimeTools（env 传 scope）。

P1diff-based 提交：不信任 journal

启示：laos 第一版 commit 靠 journal 记账，agent 用 MCP 写完文件后 changes=0 提交了个空——因为写发生在驱动进程里，记账层看不见。DSHA 的对应场景：容器内任何进程（dsh、插件、用户 PTY）都绕过 Java 层记账，所以「维护事务」的 committed 标记、备份引擎的变更检测都必须以文件系统快照 diff 为准，而不是内存/日志记账。MaintenanceTransaction 已经做对一半（改名不删、旧环境保留），把「校验归档」换成提交前 diff 快照即闭环。
附带教训：若未来为省空间用 hardlink 共享 rootfs 快照，写路径必须无条件 temp+os.replace（cow.py 的 TOCTOU 教训：先判断 st_nlink 再决定写法在并发下是竞态）。

P2stale 观察簿（多表面一致性）

DSHA 的 rootfs 同时被 3080 WebView、终端 PTY、3090 桥、ADB 桥多方写入——dsh 上下文里读过的文件随时可能被外部改掉，正是 laos 论文笔记里的 stale context 问题。最小版借鉴：3090 桥的写操作成功后，通过 AppBridge 契约向 dsh 会话注入一条 [notice] 文件 X 已被外部修改，请重新读取（bridge/HttpShellService 已有 questions 机制可复用）。

P2测试手法直接搬

  • 平台相关代码分层测：指令/字节码层离线逐条断言（DSHA 对应：终端 JNI 16KB 对齐、RELRO 检查脚本可单测其解析函数），行为层 skipUnless 真机跑；
  • 端口 0 起真 server：LanAuth / 3090 桥测试可以用真实 HTTP 客户端全链路走一遍，而不是 mock；
  • monkeypatch 常量测超时路径：RestartBudget/WebLifecycle 的时间逻辑测试可以把常量改小而不是真等。

P2能力探测报告（启动时说清降级程度）

laos 启动第一件事就是打印 IsolationReport：{level: full/partial/none, backend, reasons[]}。DSHA 可在自检报告头部加同等物：proot 是否真强制的隔离报告（link2syscall 是否生效、L2S 目录绑定是否成功、CA 包是否注入），让「降级」从开发者的隐式知识变成用户可见的一行。

不建议照搬的部分① laos 的 per-driver asyncio 锁、MCP Tasks/Elicitation——DSHA 的 dsh 自带完整的 harness，桥接层不需要再造；② BranchContext 全套 COW——proot 环境做 inode 级 COW 成本高，快照+diff 已够用；③ laosweb 的无鉴权面板——DSHA 面向真实用户，LanAuth token 门控必须保留。
