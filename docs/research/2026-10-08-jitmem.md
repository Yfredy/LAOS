## 1. 笔记抄录（◐ 转译源）

og:description（webReader 服务器侧取件）：

> JitMem 不提前把历史经验压缩成固定记忆，而是在任务到来时动态整理相关经验，并用 RL 训练 Curator 学会生成最能帮助 Executor 成功的上下文

帧图抄录（analyze_image，4/18 帧读取成功；1 帧因"图片输入格式/解析错误"未取）：

- **帧 01/18**：标题《Just-in-Time Memory：把"记什么"推迟到真正需要它的时候》。正文："传统 Agent 往往在一次任务刚结束时，就把经历压缩成固定摘要。JitMem 的反向选择是：长期保存原始成功轨迹；等新任务到来，再结合当前任务即时解释、拼装最有用的 Context。核心判断：**Memory abstraction should be late-bound. Store first, interpret when needed.**"
- **帧 02/18**（架构）：Write-time 路线 = Trajectory → Fixed Memory（Summary/Reflection/Skill Extraction）→ Future Task 检索固定 Memory；JitMem/Read-time 路线 = "当前 Task 明确后再整理"。
- **帧 06/18**（为什么有效）："传统 write-time 方法在经历产生时就整理 Memory。问题是：生成摘要时，未来 Task 还没有出现，系统已经要决定删除哪些细节。……某次经历被概括为'先改变物体状态，再完成放置'。它保留了大策略，却可能删掉'必须先移动到工具附近，再执行检查'这一条操作约束。如果新 Task 恰好需要这条约束，**再强的检索也只能找到已经缺失细节的摘要**。"

## 3. 复现记录（laos 内直接落地 = 转译复现）

"用这个系统做"——本轨道不在 laos 外复现论文实验（三基准 ALFWorld/WebShop/τ²-bench 是 LLM Agent 交互环境，需 Executor LLM 全程在线，超出 laos 零依赖核心的边界），而是把论文方法**转译进 laos 记忆栈**：

### 3.1 落地件（TDD，23 例新测试全绿，主库 884 绿）

| 件 | 内容 | 锚点 |
|---|---|---|
| `laos/jitmem.py` | `Curator`：检索→三分量自适应加权（与 recall 同源 0.7/0.2/0.1，但随成败进化）→近重复去重（文本 bigram Jaccard ≥0.6 整条丢）→字符预算**整条取舍、绝不截断原文**（top-1 豁免守卫）→kind 分组、section 内时间升序（轨迹因果连贯）→briefing 文本 | 新建 |
| `mem.curate` syscall | args `{task, k?}` → payload 文本（`payload #N task: …` 头 + 分组条目）；N 即回填句柄 | `laos/kernel.py` `_impl_mem_curate` |
| `mem.outcome` syscall | args `{payload_id, success}` → 权重自适应 + 审计；未知/已逐出 id 得 ENOSTR | `laos/kernel.py` `_impl_mem_outcome` |
| 审计 | 两个 op 均留 `event:"memory"` 审计（curate 带 stats，outcome 带 success 布尔） | 同上 |
| `tests/test_jitmem.py` | 23 例：管线 11（零相关不捞/原文不截断/整条预算/去重保高分/分组时序/确定性/只读）+ 自适应 7（成败方向/排序改变/未知 id/有界/统计/登记表封顶）+ syscall 5 | 新建 |

### 3.2 诚实降级声明（论文 → laos 的三处差异）

1. **Curator：规则版，非 LLM**。论文用 LLM Curator（Qwen3-8B 起）合成自然语言 payload。laos 零依赖红线（核心纯 stdlib）+ 无常驻本地 LLM → 规则整理（加权评分/去重/预算/分组）。论文自己实证 **untrained curator 已打平/超过 write-time 基线**，规则版是"零训练"轴上的再降一级，方向与论文一致；LLM Curator 升级路径：挂 `laos/judge.py` 云/本地后端（排队，非本波）。
2. **训练：bandit 微调，非 GRPO**。论文 GRPO 8×H200 训 21–27h。laos 落地为**首条优势归因的指数 bandit**：payload 首条（最高分入选者）相对候选池均值的分量差为归因信号（全池同质的分量如新鲜度差≈0，自动不参与归因——避免无信息漂移），成功上调、失败下调，乘性更新后归一化，学习率 0.1，登记表封顶 128（最老出队）。reward 同为**即时任务成败、时间隔为零**（论文第④步原样保留）。启发式，非 RL。
3. **轨迹库：个人记忆库，非成功轨迹筛选**。论文只收成功轨迹（Executor 充 LLM-judge）。laos MemoryStore 是个人记忆库（事实/偏好/事件），write-time 的 Jev 预审拦的是隐私/临时过程（**治理决策**），与 JitMem 批评的"质量性预压缩"不同类，二者共存；成功轨迹筛选对 laos 场景（回忆个人事实）不适用，不做。

### 3.3 BLOCKED / 未做

- GRPO 训练复现：BLOCKED-by-design（零依赖红线 + 无此量级算力；论文数字如实引用不混写）。
- LLM Curator（judge/decide 后端挂接）：排队 ◐P2（对话管线装配波之后评估收益）。
- BM25 检索：不做——laos 房型检索器是字符 bigram Jaccard（零依赖、中英文通吃），论文 BM25 是其工程选择而非主张本体。

## 4. 架构对照：论文四步循环 × laos 落点

| 论文步骤 | 论文做法 | laos 落点 |
|---|---|---|
| ① 检索 | BM25 over task descriptions，k=3 | `MemoryStore.recall`（bigram Jaccard + 标签 + 时间；零相关预过滤同样由 recall 承担），k=8（个人记忆条目粒度细于整条轨迹） |
| ② 整理 | LLM Curator 合成 task-adaptive payload（≈1.9K tokens） | 规则 Curator：自适应加权→去重→budget_chars≈1200 整条取舍→分组 briefing；**原文永不截断** |
| ③ 执行 | 冻结 Executor 带 payload 解题 | laos 调用方（agent 把 payload 文本前置进任务提示；对话管线装配波是第一个消费方） |
| ④ 回填 | 成功轨迹 LLM-judge 入库；Curator 由 GRPO 从即时成败进化 | `mem.outcome(payload_id, success)`：登记表→首条优势归因 bandit 微调三分量权重；存储库本身不动 |

## 5. laos 采纳裁决

| 论文构件 | laos 裁决 | 说明 |
|---|---|---|
| 原始轨迹保留（store raw） | ● 已有（无需改动） | MemoryStore 本就是"一个文件 + 追加写"的原文 JSONL——存储侧与论文取向天然一致，本波零改动 |
| read-time curation | ● 本波落地 | `laos/jitmem.py` + `mem.curate` |
| 即时成败回填（零时间隔 reward） | ● 本波落地（bandit 降级） | `mem.outcome`；GRPO 版需算力，不追 |
| untrained curator 有效性 | ● 已消化（设计依据） | 它是规则版 v1 的立论支点：零训练整理已有收益 |
| LLM Curator | ◐ P2 排队 | 挂 judge/decide 后端；等对话管线真实流量评估增量收益 |
| write-time 摘要/反思/技能抽取 | ○ 不做（反方向） | 论文批评的对象；laos 不引入任何 write-time 质量压缩 |
| 成功轨迹筛选入库 | ○ 不做（场景不符） | 个人记忆库收事实/偏好/事件，无"任务成败"语义可筛 |
| 三基准 SR 数字 | 引用不混写 | +16.2/+16.3/+3.9 是论文数字；laos 侧只报自己的 884 绿 |

与 esp-claw claw_memory（三层 provider + access_count + 软删，见 [2026-10-08-espclaw-vs-muse-agent-core.md](2026-10-08-espclaw-vs-muse-agent-core.md)）正交：claw_memory 治理**存储分层**，JitMem 治理**读取时机**——一个管"记什么怎么存"，一个管"何时理解"，互不冲突。

## 6. 结论

论文可信（arXiv 一手事实，笔记转译零讹变），主张与 laos 记忆栈存储取向天然同构——laos 缺的从来不是"存原文"，是"用的时候有人整理"。本波以 23 例新测试把论文四步循环（检索→整理→执行→回填）完整转译进内核 syscall 面，主库 884 绿；LLM Curator 与 GRPO 留在升级路径上，降级处全部诚实标注。记忆在使用时再被理解——现在 laos 的 agent 每个任务开始前 `mem.curate`，任务结束 `mem.outcome`，检索权重随之进化。
