## 为什么是「3 档 × 2 标记」，以及 AED 多出来的第三个维度

原始需求把音频事件模型分成「支持端侧部署 / 多模态 / 大型 / 中型 / 小型」五类，但这五类
**不在同一维度**（与 SER 同因同解）：

- **规模**（小型 / 中型 / 大型）是**互斥分档**，一个模型只能落一档；
- **端侧可部署**是能力标记，与规模相关但不等价；
- **多模态**是输入模态标记，与规模**完全正交**。

按 5 类平行收录会让同一个模型在多个文件里各写一遍，参数量与指标口径必然打架。
因此：**规模定主键，端侧与多模态作为每条记录的标记**，交叉结论在 `2026-09-landscape.md` 出。

**AED 相对 SER 多一个主键维度：任务类型。** AED 不是一个任务，至少是四个
（多标签 tagging / SED / ASC / 开放词表·零样本），**跨任务类型的指标不可比**
（mAP ≠ PSDS ≠ 准确率 ≠ 零样本 mAP）。因此每条记录必须写明任务类型，
跨档对比一律在**同任务类型内**进行。这是 AED 调研与 SER 最重要的结构差异。

## 任务类型（AED 不是单一任务）

| 类型 | 说明 | 时间定位 | 主指标 | 代表基准 | 与 laos 的关系 |
|---|---|---|---|---|---|
| **多标签 tagging** | 片段级多标签分类（一段音频可同时属于多类） | 无 | **mAP**（辅助：d′、lωlrap、AUC） | **AudioSet**（AS-20K / AS-2M full） | 常驻检测段最可能的形态：逐帧出标签，不做时间定位 |
| **SED**（sound event detection） | 事件检测 + 起止时间定位 | **有** | **PSDS1 / PSDS2**、事件级 F1、ER（error rate） | DESED、DCASE Task4 | 需要边界才知道"何时触发捕获"，成本高于 tagging |
| **ASC**（acoustic scene classification） | 场景分类，整段一个标签，**各类互斥** | 无 | **准确率** | DCASE Task1（TAU Urban Acoustic Scenes） | 不是事件检测；**不能直接套用到 tagging** |
| **开放词表 / 零样本** | 类别集在推理时给定，不固定 | 视实现 | 零样本 mAP、PSDS | AudioSet、DESED、ESC-50 | 绕开"白名单要重训"的问题，代价见 Task 4 |

三条硬规定：

1. **跨任务类型的数字不许直接比。** 一张表里出现两种任务类型时，必须分行或分表，
   并在正文写明"不同任务类型，不可直接比较"。
2. **`输出` 列必须写明任务类型**（校验器规则 g 强制），写法 `tagging/521类`、
   `SED/10类`、`ASC/10类`、`开放词表/任意类`。
3. **ASC 的结论不能外推到 tagging。** ASC 是独占单类（互斥 + softmax），
   tagging 是多标签（sigmoid + 阈值）；在 ASC 上 128K 参数能到 60% 准确率，
   **不代表** 128K 参数能做 521 类多标签。这个推论 Task 2 必须显式检验。

## AudioSet 基准口径（AED 最容易抄错的点）

| 划分 | 规模 | mAP 量级 | 说明 |
|---|---|---|---|
| **AS-20K** | ~2 万片段（balanced 子集一类的 20K 切分） | 0.3+ 属常见 | 小子集，训练/评测都便宜，**mAP 普遍偏高** |
| **AS-2M full** | ~200 万片段全量（unbalanced + balanced + eval） | **0.50 已是 SOTA** | 全量；长尾类极不平衡，数字系统性偏低 |

规定（四条，写数时必须遵守）：

1. **同一模型在两个划分上的 mAP 可差 15+ 点。** 见到 AudioSet mAP 必须先问"哪个划分"，
   没标划分的**不得入表**（校验器规则 h 强制）。
2. **`基准` 列写法**：`AudioSet AS-2M full` 或 `AudioSet AS-20K`，不许只写 `AudioSet`。
3. **优先记 AS-2M full。** 同一模型两处都有报告时，主表记 full，20K 值写进备注。
   只有 20K 值的条目可以入表，但**不得与 full 值排在同一张榜单里比大小**。
4. **balanced / 子集协议要额外标注。** 若某数字只在 balanced 子集或自定义协议下测得
   （例如某些论文报的 0.8+ mAP），必须写明协议，且**不得与全量 mAP 并列**。
5. 集成（ensemble）与单模型必须区分，写法 `mAP 0.502 (AudioSet AS-2M full, tagging, 单模型)`。

## 规模分档

按**量化前、含音频编码器**的参数量划分。边界值**左闭右开**：30M 归中型，500M 归大型。
（与 SER 完全一致，便于两篇交叉引用。）

| 档 | 参数量 | 典型部署位 | 典型延迟预算 |
|---|---|---|---|
| 小型 Small | < 30M | MCU / 手机端 CPU / 浏览器 WASM | < 100ms，可流式 |
| 中型 Medium | 30M–500M | 手机端 GPU/NPU、桌面 CPU、边缘盒子 | 100ms–1s，近实时 |
| 大型 Large | > 500M | 服务端 GPU，或端侧仅量化后可用 | > 1s，批量 |

口径说明（四条）：

1. **含音频编码器**：音频编码器 + 标签头 / LLM 两段式的，参数量写**两段之和**，
   并在「版本/权重」列注明结构，否则大型档会系统性偏低估。
2. **量化前为准**：INT8/INT4 后的体积写进 `edge` 列，不改写 `参数量(M)`。
3. 纯特征工程方法（如 openSMILE + SVM）无神经参数量，写 `n/a(非神经)`。
4. **AED 补充：参数量不是唯一约束。** 端侧是「参数量 + MACs」双约束——
   DCASE Low-Complexity ASC 的硬指标是 **128K 参数 / 30 MMACs**，只看参数量会误判。
   凡涉及端侧的记录，`指标` 列要带 MMACs 或等效计算量。

## 跨切标记

### `edge`（端侧可部署）

合法取值：

| 值 | 含义 |
|---|---|
| `yes: <runtime+量化>` | 有公开转换案例或官方端侧导出路径；必须带 runtime 名与量化方式，例：`yes: TFLite INT8` |
| `no` | 需要服务端 GPU，或参数量/显存明显超出端侧 |
| `unknown(未找到公开转换案例)` | 没有证据，不等于不行——这是合法值，不算 TBD |

runtime 覆盖：TFLite / TFLite Micro、ONNX Runtime Mobile、CoreML、NCNN、MNN、RKNN、
**QNN（Qualcomm AI Engine Direct，与 laos 现状直接相关）**。

**「yes」在本仓库还要再分一层**（沿用 SER `04-edge-deployment.md` 已确立的两档）：

| 档 | 含义 | 功耗口径 |
|---|---|---|
| **A 档 · 真端侧** | 原生 App / aDSP / Sensing Hub / 手机 NPU | mW 级常驻；但第三方 App 拿不到 aDSP，能拿到的 HTP 在瓦级 |
| **B 档 · proot 内** | CPU 推理（`pip install` 即可跑） | 通用 Linux 空闲 **400–1000 mW**，拿不到 aDSP 的 mW 档，**绝不能常驻** |

落到 AED 的具体论证在 `05-edge-deployment.md`（Task 5），本文件只定口径。

### `模态`

用字母组合，不用中文描述：

- `A` = 音频（声学）
- `T` = 文本（类别名集合 / 查询文本 / ASR 转写稿）
- `V` = 视觉（画面、唇动）

例：`A`（纯声学）、`A+V`、`A+T`、`A+T+V`。
**开放词表的类别提示算不算 `T`，见下文「口径裁定记录 · 裁定 1」。**

## 指标

每个指标值**后面必须跟基准名与任务类型**，不写裸数字：

- `mAP`：多标签 tagging 的主指标
- `PSDS1` / `PSDS2`：polyphonic sound detection score，SED 主指标
- `准确率`：ASC 主指标（独占单类才用它）
- `事件级 F1` / `ER`：SED 辅助
- `零样本 mAP`：开放词表
- 工程指标另记：**MMACs**（或 MMACs/s）、RTF、峰值 RSS、模型体积 MB、功耗 mW

写法示例（三条，覆盖三个任务类型）：

- `mAP 0.502 (AudioSet AS-2M full, tagging)`
- `PSDS1 0.422 (DESED, SED)`
- `61.47% (DCASE2025 Task1, ASC)`

**不同基准、不同划分、不同任务类型的数字不许直接比。**
跨档对比必须同基准同任务，否则在正文里明说"不可直接比较"。

## 红线与约束

1. **每条记录必须可核验。** `来源` 列必须有 arXiv ID / HuggingFace repo / GitHub 链接之一
   （校验器规则 c）。查不到就删除该条，不留"待补"。
2. **许可必须记录，AudioSet 要写全现实。** 权重许可与数据集许可都写，商用受限
   （NC、自定义研究用途）要标出。**AudioSet 特殊**：本体与标签是 **CC-BY**，但
   **音频本体是 YouTube 视频，且官方已停止分发完整包**——实际使用几乎不可能拿到原始音频，
   通行做法是第三方镜像或**官方/第三方预计算 embedding**（如 PCA/embedding 发行版），
   而这些镜像的可用性、完整性、许可合规性各不相同。
   因此：凡引用 AudioSet 数字，**必须写明"（预训练/评测语料为 AudioSet，音频本体不可直接获取，
   实际复现依赖第三方镜像或预计算 embedding）"**，不许只抄一句 "CC-BY"。
3. **参数量统一口径**：单位 M = 10⁶，量化前，含音频编码器；非神经写 `n/a(非神经)`。
4. **计算量必须同时记录**：凡涉及端侧的记录，`指标` 列带 MMACs 或等效计算量。
5. **指标必须带基准名与任务类型**，不写裸数字；不同任务类型、不同 AudioSet 划分的数字
   不许直接比。
6. **不存声纹；事件标签不单独触发留存。** 带说话人识别/验证能力的模型在「版本/权重」列标注
   `speaker-capable` 且不参与选型。AED 输出只能改变"是否蒸馏"，**不能改变"是否留存原始音频"**，
   否则 laos「原音频即焚」架构被绕过（落地约束，Task 8 展开）。
7. **中文场景空白不得用英文基准冒充。** AED 领域没有 SER 那样的中文基准
   （无 MER/M3ED/CHEAVD 的对等物）。AudioSet 源自英文 YouTube，中文家庭环境事件分布不同
   （电动车报警器、麻将、广场舞、燃气灶报警器等）。这个空白与后果由 Task 7 如实记录，
   **不得拿英文基准结论宣称中文可用**。

## 口径裁定记录（执行过程中产生）

### 裁定 1：开放词表提示算不算模态

沿用 SER 裁定 3 的精神（「模态列记**推理时的输入通道**，不是训练期用到的模态」），
延伸到 AED 的开放词表情形：

| 情形 | 记法 | 理由 |
|---|---|---|
| 固定 system/instruction prompt（如"列出这段音频里的声音事件"） | **`A`** | 不携带事件信息，且不随输入变化；否则几乎所有 LLM 都会变成 `A+T` |
| 开放词表的**类别名集合**由调用方在推理时给定 | **`A+T`** | 类别集**决定输出空间**且逐次变化，是真实的输入通道 |
| 检索式 / 查询式 SED（query text 逐次变化） | **`A+T`** | 同上，文本是真实输入，不是装饰 |

两条细则：

- **训练期的文本教师不计入**（沿用 SER 裁定 3 第 2 条）：用 CLAP/文本编码器做对齐或蒸馏教师、
  推理时只吃音频的模型记 `A`，在「版本/权重」列注明"文本仅作训练期对齐/教师"。
- **内部有文本 tokenizer 不等于有 T 通道**：音频 LLM 用文本 decoder 生成标签，但如果
  prompt 是固定的、类别集也是固定的，仍记 `A`。

**推翻条件**：本裁定为**初始裁定**。Task 4/6 若找到反证——例如某论文明确说明
"类别提示只作权重调制（如 FiLM / prompt tuning），不构成输入通道"，或某开放词表系统的
类别集在推理时固定不变且不可调用方指定——**可以推翻，但必须在裁定记录里写明证据与出处
（论文章节或官方文档原文），不得静默改写**。届时在此追加「裁定 1 修订」。

### 裁定 2：速览版的规模分档与本文件冲突，以本文件为准

`docs/research/2026-09-11-aed-agc-model-landscape.md`（速览版）有两处与本文件冲突，
