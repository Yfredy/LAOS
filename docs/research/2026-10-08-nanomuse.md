## 1. 一句话结论

**nanoMuse 是两周大、单人驱动（lgy0404，834/861 commits）但完成度惊人的"开源 Muse"**：把个人 agent 做成全设备（Android proot+Alpine/iOS 无手/桌面 Electron/Linux Docker）可跑的 GPL 产品，其 **Sentinel 动作闸（六级有序判定 + taint 追踪 + scoped grants）是全仓最值得 laos 学习的构件**；它诚实地自认"policy boundary, not privilege boundary"（macOS/Windows 无沙箱、正则绊线可被对抗脚本绕过）——**这句话恰好是 laos 能力位+seccomp 特权边界的差异化定位**。论文本身是设计报告而非评测（"the number does not exist yet, and we would rather say so than estimate it"）。

## 2. 论文骨架（arXiv:2610.08699）

### 2.1 五问定义个人 agent（§4）

| 问 | 要点 |
|---|---|
| What it knows | 记忆=人可读可编辑的普通文件；需要 provenance（写入模型/日期/置信度）；调和规则："**人写的一行胜过模型写的任何行**" |
| Where it acts | 一个 agent 多双手；每个有屏/麦/马达的设备都是一双手和一扇门 |
| Whom it answers to | 审批=小型常规信任语言：scoped grants（once/本会话/always-for-recipient）、可见可撤销；支付/密码**永不记忆** |
| How it learns | 可见可调的中断条；共享 traces 训开放模型；终局端上学习 |
| How it is paid for | 小到能在家跑；直付或最便宜档自托管 relay（实测 ¥30-60/月或 $4-6 + 模型费 ¥2/8 每 Mtok） |

三地平线（Fig.4）：2026 现有 → 开源对照补齐 → 服务多年的 agent（记忆/身份跨模型跨设备跨厂商存活）。

### 2.2 Sentinel（论文 §5 + 源码，两者互证）

固定判定序六步：denied tools → 用户规则 → always-allow/always-ask 列表 → **taint**（读过隐私数据后，出站调用变 ask，**永不回退**）→ 工具风险×用户模式 → 不可覆盖警告（破坏性 shell/管道下载执行/标签里的承诺词）。批准即绑定 tool:target 的 capability（五档寿命）。自述局限：策略边界非特权边界——与 agent 同信任域（Muse 用的是 agent 够不着的机制）。

### 2.3 Muse 复刻段（§3，逐句来源标注）

观察十项易读性决策（单 agent 有名有脸/一条长会话/工具调用 chips/scoped 审批卡/记忆即文件/五房间/暗化 live stage/默认显示步骤）；生产 prompt 复刻（persona 优先/只服务一人/硬停清单/VM 约每小时换但家目录持久/真 Chromium 带 cookie/子 agent 一层/两层记忆先搜后忆/**三个 agent 自留文件用 OpenClaw 的文件名**/模型为编号 Muse Spark release）；文档化事实（**每人一台 Linux VM + seccomp 容器 + Sentinel 为唯一权限权威 + 代理令牌 + 内核 taint 追踪** + 仅可访问性树的浏览器观测 + 结账检测器强制审批）；推断（沙箱渲染器/特权代理二分解释了 VM-per-person 经济账）。**这份复刻是 laos"内核治理"叙事迄今最强的商业印证**——Muse 的权限面就是 seccomp+taint+Sentinel 三件套。

### 2.4 成本与评测

App 38MB（Android arm64）/桌面 256-498MB/内存 ~0.5GB；relay 一进程+SQLite ~85MB（1vCPU/1GB 够用）。**无任何成功率数字**（明说不愿编造）；评测套件在路线图（AndroidWorld/OSWorld/MemGUI-Bench/OS-Harm 之侧从失败 run 建套件）。

## 3. 源码级拆解（API 直读，锚点为仓库路径）

### 3.1 Sentinel 实现（`nanomuse/sentinel/` 四文件）

- **接缝**：agent 主循环每个工具调用过 `sentinel.guard()`（`agent/core.py:495`）；数据流 `agent → guard() → policy → grants/approval → vault.resolve → execute → redact`（`gate.py:1-10`）。
- **风险自描述**：每个工具实现 `BaseTool.assess()` 返回 `CallAssessment{risk, reads_private_data, egress, egress_target, ...}`（`tools/base.py:29-47`）——**风险元数据跟工具走，不是中央注册表**。
- **六级判定**（`policy.py:72-143`）与论文一致；**MCP 工具同样过闸**：`MCPTool(BaseTool)` 且 risk/egress/reads_private_data 可按 server 或按工具覆盖（`tools/mcp_tools.py:147-169`）。
- **warnings 永不被 grant 覆盖**：`grant_options()` 对带 warnings 的调用只返 `["once"]`（`gate.py:108-113,203-206`）——危险命令每次都问。
- **不可逆拦截双层**：shell 危险正则表 `_DANGEROUS`（rm -rf/sudo/mkfs/curl|sh/git push --force 等，`tools/shell.py:79-90`）+ Python 脚本六类"触达面"静态扫描 code_reach（network/processes/env/dyn-code/deletion/outside-workspace，`shell.py:97-163`）。
- **授权=能力**：五档寿命 once/conversation/session/24h/always；`shell:git` 只许 git 不许 curl（管道逐程序解析，`shell.py:166-188`）；pipeline 多目标须逐一覆盖（`grants.py:142-163`）；24h/always 持久化 JSON。
- **密钥面**：vault 占位符 `{{vault:NAME}}` 批准后执行前解析、结果再 redact（`gate.py:286-332`）；子进程环境先洗掉类凭据变量（`shell.py:32-53`）。
- **测试**：`tests/test_sentinel.py` 20 例（host_allowed/风险×模式/规则序/auto 下 warnings 仍问/污点→egress/grant 生命周期/pipeline 组合/vault redact）。

### 3.2 记忆（双线两实现，README 的"Markdown"只对了一半）

- Python 线（桌面/服务器）= **SQLite 四表**（memories/memory_log/memory_meta/memory_vectors，`memory/store.py:100-146`）；检索=bigram 重叠+log(N/df) 稀有词加权（可选 embeddings 融合）；**整理=模型提议、模块裁决**：合并不得发明新词、**用户手写行永不删**、单次最多删 20%（至少留 4 行）、每变更带 before/after 可 undo（`consolidate.py:1-46`、`store.py:309-375`）。
- Android 线（OpenMinis 底子）= Markdown：`minis-global/memory/GLOBAL.md`（用户维护、agent 只读）+ 每日 `YYYY-MM-DD.md`（`MemoryRepository.kt:11-14,253-266`）。
- **provenance 现状=只有 source("agent"/"user")+时间戳，无回链到对话/消息**——论文承认是路线图。**这是 laos 可以先做掉的空位**（laos 有 audit epoch|seq，回链是现成的）。

### 3.3 其余构件（速记）

- agent loop：`MuseAgent.run()`（`agent/core.py:378-536`）max_steps=30、卡死检测、上下文裁剪 80 条/4 图、用户插话 drain inbox。
- 18 providers 全收敛为 OpenAIChat/Responses 两协议类+PromptToolAdapter（`llm/factory.py:19-41`）。
- relay：REST+单调 change counter，push 幂等 ≤200 条/请求，pull since 游标；**"Never a file, never a picture"**（只存文本+附件名和大小，`cloud/sync.py:4-7`）；hub 设备互操的命令**在发起端先过审、接收端不再问**（`hub/actions.py:4-6`）。
- 桌面之手：脑在 Python、手在 Electron（UI-TARS nut.js 移植，loopback HTTP，`computer/operator.py:1-33`）。
- 隔离三条腿：手机 proot/桌面 Linux bubblewrap（`sandbox.py:1-24`）/macOS+Windows **无沙箱**；docs 自列 "Not covered" 清单（`docs/sentinel.md:126-134`）。

## 4. laos 对照（七构件）

| nanoMuse 构件 | laos 对应物 | 判定 |
|---|---|---|
| Sentinel 六级判定序 | laos 闸门链 caps→task_scope→不可逆闸（仅 risk=high 才 confirm） | laos 缺有序策略引擎与风险×模式矩阵——**学** |
| **taint 追踪**（读隐私→出站变 ask 永不回退） | 无 | **学（本波主件）**；Muse 文档化设计同样有 kernel taint |
| scoped grants（五档寿命/target 绑定/可撤销） | confirm(op)→bool 一次性回调 | **学（简化为 once/session/always 三档）** |
| warnings 终审（显式规则才能放行） | irreversible+risk=high→confirm | 语义相近，吸收进 sentinel 判定序 |
| 记忆 provenance + "用户行胜模型行" | MemoryStore 无 origin 字段 | **学（audit 回链先做掉他们的路线图）** |
| relay/hub/桌面之手/聊天渠道 | 核心域外 | ○ 不做（记录架构事实供引用） |
| 隔离（proot/bwrap/无沙箱自认） | caps 能力位+seccomp（demo 已证特权边界） | **差异点=laos 定位**：他们自认 policy 边界，laos 做的是 privilege 边界 |

## 6. 结论

nanoMuse 用两周把"Muse 应该开源成什么样"答卷写到了 297★ 的完成度，其 Sentinel 是目前开源界**最认真的个人 agent 动作闸**（六级判定+taint+scoped grants+20 例测试+密钥面闭环）。它留给 laos 两样直接可取的（策略引擎/授权寿命与 taint）、一样可以抢先做掉的（provenance 回链——他们还停在路线图），和一句话的定位礼物：**"policy boundary, not privilege boundary"——laos 做的正是他们没有的那一半**。
