## 1. 一句话结论

**ARVIS 是"级联式全双工"当前最完整的开源工程参考**：AEC3 回声消除打底（说话时也能听）+ 双档打断路由（关键词保守门 / 0.6B 小模型语义路由 wait-continue-yield，**用 jev 协议问句、和 laos 判断层同方言**）+ 贯穿全管线的话轮 revision 化（投机话轮可"重开"）。对 laos 最重要的一句话差距：**laos 的 TurnPolicy 是纯时序三态——用户开口即 stop；ARVIS 证明"开口"必须再分三类：打断（cancel）/ 附和（backchannel，装作没听见继续说）/ 意图不明（wait，反问澄清）**。这三分类 + 播报时窗 + 模型不得伪造系统信封，是本报告的三个采纳裁决；AEC3 直绑因零依赖红线走驱动子进程参照路线。

## 3. 级联式全双工（cascaded-full-duplex）

### 3.1 管线与两个并发原语

管线 = 队列串联的 handler 链 `VAD → STT(+TranscriptionNotifier) → LLM → LMOutputProcessor → TTS`（s2s_pipeline.py `_build_handlers`），每会话一个 `PipelineUnit`（自带全部队列与状态），一个 RealtimeServer 挂 `num_pipelines` 个 unit 组成池。`should_listen` Event 是管线级半双工门；本地客户端另有 `block_mic_during_playback` 选项（播报时物理闭麦——与 laos MicrophoneGate 同思路的兜底档）。

**CancelScope**（cancel_scope.py，44 行）：代数计数器 + `discarding` 丢弃旗。`cancel()` 使 gen+1，管线线程在响应起点捕获 gen、沿途 `is_stale(gen)` 检查；发送环在 `discarding=True` 期间静默丢弃陈旧输出。**与 laos dialogsched.GenerationGate（interrupt()/is_current()）同构** ●互证——两边独立演化出同一原语，说明"打断=版本化作废"是这类系统的收敛解。

**SpeculativeTurnTracker**（speculative_turns.py，417 行）：比 laos PauseWindow 深一档的话轮并发控制。核心概念：

- 每个话轮带 `turn_id + revision`；STT 增量、LM 输出、TTS 提交**每一级都先问 `is_latest`** 再放行——陈旧 revision 的产物在管线上任意一级被丢
- **投机重开（reopen candidate）**：话轮已闭、STT 已提交，但用户又开口了——先 `begin_reopen_candidate`（base_rev→base_rev+1 的候选号），确认后 `confirm_reopen_candidate` 把 latest 推到新 revision，之前的提交全部作废；2.0s 等待超时强制落地
- **重开宽限窗（reopen grace）**：话轮要提交前先 `start_reopen_grace(grace_s)` 等一段——给"用户其实还没说完"留窗口，宽限期内提交被挡
- 2048 话轮 LRU 剪枝，全部状态 Condition 锁保护

对照：laos PauseWindow 的 `prepare_candidate/commit_decision/take_cancelled` 处理的是**同一问题**（暂停期的投机 prefill 该不该放行），但 revision 只到 dialog 级、没有"已提交话轮重开"语义。ARVIS 这套是"用户说完半句停顿又继续"的完整状态机。

### 3.2 打断路由 keyword 档：TurnController 保守门

turn_controller.py（98 行）——**VAD 只说"有语音"，不说"是打断"**。助手说话期间收到用户语音，先挂起为 barge-in 候选（绑定 turn_id+revision+response_key，不立即取消），等 STT 出字再判：

| 判定 | 条件（按序） | 动作 |
|---|---|---|
| CANCEL | 转写以 9 个显式打断短语之一开头（"等一下/停/暂停/不是这个意思/我换个问题/打断一下/先别说"…） | 作废当前响应，让位 |
| BACKCHANNEL | 整句命中 13 词附和白名单（"嗯/嗯嗯/啊/哦/对/好的/知道了/继续/yes/yeah/ok/okay"…） | **装作没听见：话轮不进 chat、不触发响应，助手继续说** |
| CANCEL | final 转写且非 backchannel | 终稿权威，让位 |
| WAIT | 语音时长 < 280ms | 继续等 |
| CANCEL | ≥3 个有效字符，或含疑问/行动标记（"吗/什么/怎么/哪里/哪个/帮我/请/我想/我要"） | 让位 |
| WAIT | 其余 | 继续等 |

细节两处值得抄：①规范化先剥全半角标点+空格再匹配（normalize 正则）●；②backchannel 判定要求**整句**精确命中白名单——"嗯，但是…"不是附和。

### 3.3 打断路由 semantic 档：jev 协议语义路由

`S2S_SEMANTIC_TURN_URL` 指向本地小模型服务（默认 `http://127.0.0.1:8792/v1/systemone`），`SemanticTurnRouter.decide()` **同步** urlopen、**120ms 超时**（semantic_turn_router.py:31）。规则（service.py `_on_semantic_transcription_completed`）：

- **首句豁免**：唤醒后的第一句永远不是 barge-in（唤醒应答可能还在播）——因为用户对着空气开口是这个交互模式的家常便饭
- 首句之后的**每一个完整话轮**都问模型：助手刚说了什么（滚动 4000 字符）+ 用户刚说了什么 → continue / yield / wait
- **CONTINUE**：不打断，当前响应继续，用户话轮只进上下文不触发新响应
- **YIELD**：作废当前响应，用户话轮按正常新话轮处理
- **WAIT**：作废当前响应 + 用户话轮进 chat + **定向生成澄清问句**（instructions 追加"用户刚才的话意图尚不明确。请……提出一个简短、具体的澄清问题……不要擅自推断意图或直接执行任务"，`tool_choice="none"` 锁死工具）●
- **失败保守**：语义服务异常 → 保留当前响应不动 + 发 error 事件（宁可不打断也不误打断）；每个决策（含失败）全量进日志

### 3.4 声学层：WebRTC AEC3 ctypes 桥

aec3.py（116 行）+ native/aec3：vendored `webrtc-audio-processing` 2.x，C ABI 小适配器开真 AEC3（`mobile_mode=false`）。**render 路径喂"正在往扬声器写的 PCM"（ProcessReverseStream），capture 路径处理麦克风（ProcessStream），10ms 单声道帧**，输出即"扣掉回声后的用户声"。音频客户端在回调里双路并行（audio_client.py:1042-1077）：写扬声器的同一块 PCM 进 render，读到的麦克风块过 capture 再进唤醒门控与上传。构建脚本仅 macOS（build_macos.sh）；Linux/Windows 部署文档在 cascaded README 单列（WSL2 也有部署路径 ●README）。

这是"助手说话时也能听"的物理前提——没有 AEC，扬声器声音会灌回麦克风，VAD 会把助手自己的声音当用户语音。**laos 的 MicrophoneGate.allow(aec_ready, barge_in_enabled) 早已预留 aec_ready 参数位**，当时的设计预留与 ARVIS 的实装路径吻合。

### 3.5 桌面唤醒与端点检测

- desktop/src/wake-word/sherpa-detector.mjs：**sherpa-onnx KWS**（transducer encoder/decoder/joiner + tokens + keywords 文件，16kHz/80 维特征，`keywordsThreshold 0.25`，`modelingUnit cjkchar`）——与 laos wakegate KWS 实测（zipformer 3.3M int8，7.56ms 中位/零误报）**同款选型** ●互证
- VAD/smart_turn.py：集成 pipecat **Smart Turn v3.2** ONNX——仅在 Silero 找到"语音→静音"边界后调用，对 ≤8s 音频判"这句话说完没有"（语义端点检测），不逐块跑。与 laos turnpolicy 的 tail_silence_ms=500 固定阈值互补：ARVIS 用模型把"尾部静音多久算说完"变成逐句自适应

## 4. qwen-audio-agent：前台 Agent—编排运行时—后台 Agent

server/src/README.md（中英双语导航）定义逻辑架构：**前台 Agent（对话+工具）— 编排运行时（Gateway 是宿主不是对等组件）— 后台 Agent（执行体）**。对照 laos 叙事：这正是"内核调度多类负载"的用户态实现——前台/后台都是被编排的负载。

**后台适配器族**（backend/adapters/）：ACP 协议驱动 claude/codex/codebuddy/openclaw（含 openclaw-delegation 委派）/opencode/pi/deepseek-harness/generic-acp/local-acp/private-file，另加 A2A 与 **muse**（nanoMuse 互认，两个学习对象在此握手）。每个驱动是独立文件，权限走 permission-broker、串行走 keyed-serial-executor。

**语音域**（voice/）三个与 laos 直接相关的构件：

1. **播报时窗 AnnouncementWindow**（announcement-window.mjs，89 行）：后台任务完成想说话？三条件全空才准——用户没在说话（userSpeaking）、当前话轮没有未落地的响应（turnPending）、没有排队中的音频（audioResponses）。播报自身的 origin='announcement' 绕过自身；用户开口即 interrupt() 让位。后台任务播报不和用户抢嘴的**最小正确状态机**
2. **response-guards 保留信封**（response-guards/）：`<gateway_system_event>/<permission_request>/<background_work_progress>/<restored_context>` 四种 XML 信封**只能由 Gateway 注入，模型输出中出现即违规**——守卫命中后带纠正指令重问（"你刚才输出了只能由 Gateway 提供的内部事件格式……不要编造协议标签、标识或执行状态"），且纠正前先验 turn 仍当前（turnId+generation 双匹配）。守卫注册表 Object.freeze 静态——加守卫是代码评审行为不是运行时配置
3. **providers 协议适配族**：dashscope / **doubao-seeduplex**（豆包全双工协议+protocol 分层）/ google-live / gpt-live / minicpm-o / stepfun / s2s 各自成对（`X.mjs` + `X-protocol.mjs`）——每个实时语音后端一个薄协议层，与 laos"驱动子进程"分层同思路

**任务域**（task/）：task-manager/scheduler/**recurrence（周期任务）**/**reminder-scheduler（提醒）**/notification-queue/**recovery（崩溃恢复）**/artifact/state/store 十二件 + **permission-policy**：per (owner, session) 的 mode ∈ {ask, auto_allow}，TTL 6h、LRU 上限 500 会话，决策绑定 taskId，任务终态自动清 pending。对照 laos Sentinel grants（once/session/always 五档+target 绑定）——**判定粒度 laos 更细，会话级 TTL/LRU 上限的内存治理 ARVIS 更严谨**（laos grants 目前无 TTL 无上限）。

## 5. 端到端侧（○不采纳定位）

end-to-end-full-duplex/ 是训练代码（Qwen3 骨干+Mimi 编解码+Moshi 式联合建模，trainer+dataset+models）。对 laos 定位为**认知参照**：laos 不训模型（零依赖红线），但报告留档一件事——级联 README 明言"后续将推进端到端全双工模型训练"，即作者自己把级联路线当作过渡态、端到端是目标态。这与 laos 三轨调研结论一致（全双工的终局是联合建模，工程价值在级联过渡期）。

## 7. 采纳裁决（学设计零拷贝，Apache-2.0 本就允许但纪律不变）

- **R1 采纳｜backchannel 白名单进 turnpolicy/dialogsched**：助手说话期间的用户语音先过附和白名单（中英 ~13 词起步，整句精确命中，规范化剥标点），命中则不 stop、话轮不入队不触发响应。最小改动：TurnPolicy 增一态或 dialogsched 在 stop 前插一道过滤。这是全双工体感的最大单项收益（用户"嗯嗯"跟听不再打断播报）
- **R2 采纳｜语义话轮路由作为 turnpolicy 的可插驱动**：默认仍纯规则（零依赖不变）；提供 judge 注入位——输入 (assistant_tail, user_asr) 输出 continue/yield/wait，120ms 预算、超时/异常一律落回规则档（ARVIS 的失败保守方向），首句豁免与 WAIT 反问（tool_choice 锁死）照抄语义。laos 的 jev.py 判断层已说同方言，等于把现有零件接到新用途
- **R3 采纳｜后台播报时窗**：dialogflow 播报路径加 AnnouncementWindow 语义（用户说话中/话轮未落地/音频排队中 → 阻塞等待，用户开口即让位）——evroute 已经管"该不该投递"，时窗管"什么时候说"，互补
- **R4 参照｜豆包 SeedUplex 协议分层**：排队中的豆包 TTS/全双工任务，动工时照 X.mjs+X-protocol.mjs 的适配分层写法（协议层薄、能力层厚），少走弯路
- **R5 参照不直搬｜AEC3 驱动子进程**：真全双工的声学前提。laos 零依赖红线 → ctypes 直绑不进核心；未来实装走"驱动子进程持 webrtc-audio-processing，stdin/stdout 传 10ms 帧"，MicrophoneGate 的 aec_ready 参数位即接入口（aec_ready=False 期间维持现有半双工闭麦兜底，渐进不破坏）
- **R6 不采纳｜端到端训练侧**：不训模型（既定红线）；认知留档（级联=过渡态，联合建模=目标态）
