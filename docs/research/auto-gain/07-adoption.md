## §1. 落地前先读 HY4 捕获链路（已读）

### (a) 当前录音源与是否已存在增益/归一化处理

- `aor/drivers/rec.py`：`_real_factory` 用 `sounddevice.InputStream(samplerate=16000, blocksize, dtype)` 采 16 kHz PCM；
  **没有任何增益/归一化/AGC 环节**，VAD 门控后直接 `encode_segment`（Opus 优先，降级 WAV）。
- `aor/drivers/ear.py`：`transcribe_file` 从 PCM 字节直接算 `dbfs = rms_dbfs(unpack_pcm16le(pcm))`，
  再喂 `classify_mood(dbfs, dur_ms)`。**录音链路目前是"直采直存"，电平即真实电平。**

### (b) `classify_mood(dbfs, dur_ms)` 的 `dbfs` 怎么算 —— 副作用必须写明

`dbfs` 来自**未处理的原始 PCM**（`ear.py:146`）。**若 AGC 施加在它之前（采集前或采集后写盘前），
电平被归一化后，`dbfs` 就失去"这个人说话多大声"的信息**——`classify_mood` 的"高唤醒/低唤醒"标签会退化成
"归一化后都差不多响"，可用性直接塌掉。这是真实副作用，不是理论风险。

### (c) 若加 AGC，加在哪：写盘前 vs 只送推理前

- **写盘前（影响留存）**：归一化后的音频被 `rec.gc` 留存副本也带着，且 `dbfs`/情绪记忆被污染——**禁止**。
- **只送推理前（不影响留存）**：ASR 拿到归一化音频，但 `classify_mood` 仍需在**原始 PCM** 上算 `dbfs`。
  即便如此，闭环增益仍会与固件环形成二次增益（见 `01` Part 0），故不推荐。

## §2. 落地建议（按 Task 15 决策表）

### 2.1 本仓库的具体动作：**不加采集后闭环增益**

| 维度 | 本仓库现状 | 决策 |
|---|---|---|
| 是否已过 TX-path AGC | 不确定，需真机验证（`01` Part 0.3） | 默认视为"可能已过"，**避免再加闭环增益** |
| 能否拿 aDSP | 不能（proot，见 `05` §1） | 排除采集前层 |
| 是否常驻 | 是 | 闭环增益常驻 = 二次增益泵浦风险 |
| 是否允许联网 | 离线优先 | 排除云端增益 API |
| 目标 | ASR / 情绪蒸馏质量（非听感） | 不需要听感级 AGC |

→ **结论：不加采集后闭环增益。** 若只是想让送审/留存的电平一致，唯一被放行的形态是
**离线开环响度归一（laos.loudness / pyloudnorm，−24 LUFS，GY/T 282-2014）**，
且**只对送 ASR 的那份副本做**，原始 PCM 的 `dbfs` 仍按 (b) 在原始副本上算。

### 2.2 若未来要加（触发条件）

仅当**真机线性度测试（`01` Part 0.3）证明链路未过 AGC 且设备支持 `UNPROCESSED`**，
且**走出 proot 做成原生 App 拿到 aDSP/Sensing Hub** 时，才考虑在采集前层挂 WebRTC AGC2。
在此之前，保持"不加"。

### 2.3 不做什么（三条）

1. **不在采集前层做**：第三方 App 拿不到 aDSP 的 SEE/LPAI（内核 fastrpc `attach audioPD` 返回 `-EACCES`），
   就算做了也跑不到省电档。
2. **不引入生成式修复**：会补出输入中不存在的内容（Task 12 幻觉风险），污染转写与情绪记忆（与即焚架构根本冲突）。
3. **不让增益作用于留存副本**：任何增益只作用于送推理的副本；`rec.gc` 删的是原始音频，增益参数随之一并焚毁。
