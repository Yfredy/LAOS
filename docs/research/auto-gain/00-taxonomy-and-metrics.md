## 为什么不是 5 类平行，而是「经典 DSP 档 + 3 档 × 2 标记」

原始需求把自动增益分成「支持端侧部署 / 多模态 / 大型 / 中型 / 小型」五类，
但这五类**不在同一维度**（与 SER 同因同解）：

- **规模**（小型 / 中型 / 大型）是**互斥分档**，一个模型只能落一档；
- **端侧可部署**是能力标记，与规模相关但不等价——几十 M 的模型也可能跑不到实时，
  而经典 DSP 反馈环根本没有参数量却最容易常驻；
- **多模态**是输入模态标记，与规模**完全正交**（AGC 领域预期实质为空，见 `06-multimodal.md`）。

按 5 类平行收录会让同一个条目在多个文件里各写一遍，作用点与控制对象口径必然打架。
因此：**规模定主键，edge 与多模态作为每条记录的正交标记**，交叉结论在
`2026-09-landscape.md` 出。

### AGC 的一处扩展：经典 DSP 档不是第四档

AGC 与 SER/AED 最大的结构差异：**本领域的主力形态没有参数量**——业界常驻链路上的
AGC 是经典 DSP 反馈环（WebRTC AGC2、SpeexDSP 一类），不是神经网络。

处理方式**不是新开第四档**（那会让规模分档失去跨领域可比性，SER/AED 的交叉表就没法对齐），
而是：

- `参数量(M)` 列写 `n/a(非神经)`，与 SER 已有的纯特征工程写法（`openSMILE + SVM`）完全一致；
- 这些条目**集中放在 `01-classical-dsp.md`**，作为一个与三档并列的文件，
  在 landscape 交叉表里占**独立一行**；
- 三档边界**不变**：`< 30M / 30M–500M / > 500M`，左闭右开。

**预期结论（要由 Task 2–5 的调研证实或证伪，不是定论）**：AGC 的神经网络模型几乎全部
落在小型档，中型稀疏，大型档只有生成式音频修复、且严格说不是 AGC。若调研结果如此，
在 landscape 里给出解释；若相反（比如中型档其实很丰富），**同样如实写，并回到本文件
追加一条口径裁定记录推翻该预期**。

## 作用点（AGC 的第一列语义）

增益可以加在四个完全不同的位置。**加错层的后果不是效果差，而是削波与增益泵浦**
（在已做过增益的信号上再加一次闭环，等于两级环路互相追逐）。
因此这是每条记录都必须填的列，由校验器规则 `stage` 强制。

| 作用点 | 位置 | 谁能做 | 关键约束 |
|---|---|---|---|
| 采集前 | ADC 之后、音频 HAL 之前（TX-path 固件 / ADSP / PGA） | SoC 厂商、固件、OEM | **第三方 App 通常改不了**；Android 上普通 App 拿不到 aDSP 的 SEE/LPAI（见 `05-edge-deployment.md`，沿用 SER 04 的权限隔离结论） |
| 采集后 | App 或 proot 拿到的 PCM 之后（AP 用户态） | 应用层 | 唯一可选层；**若固件已做过增益，此处再加就是二次增益**——此问题由 `01-classical-dsp.md` 先行回答，结论决定后续所有 Task 走向 |
| 播放前 | 解码之后、DAC 之前（RX-path） | 系统 / 播放器 | **与"录音"无关，不参与选型**；收录仅为了排除，避免把 RX-path 组件误记成采集链路能力 |
| 离线 | 对已存文件批处理 | 任意 | 与「原音频即焚」架构的兼容性要单独论证（见 `07-adoption.md`）；常驻链路用不上 |

两条填写细则：

1. 一个组件跨多个作用点（如 WebRTC AGC2 的模拟段在采集前、数字段在采集后），
   **都写上**，用顿号连接：`采集前、采集后`。
2. 只写"能不能在这层跑"，不写"我们该不该在这层加"——后者是 `07-adoption.md` 的结论。

## 控制对象（这一列把 AGC 与相邻领域分开）

| 值 | 含义 | 备注 |
|---|---|---|
| 数字增益 | 对 PCM 样本乘系数 | 最常见；无硬件依赖 |
| 模拟增益 | 调 ADC / PGA 前端放大倍数 | **需要硬件通路**，第三方 App 通常不可达 |
| 响度(LUFS) | 以 ITU-R BS.1770 系列定义的响度为目标量的闭环 | 与"峰值/RMS 检测"不是一回事 |
| 降噪掩码 | 频点 / 时频掩码，本质是增强 | **降噪 ≠ 增益控制，不许混记**；只有当该模块同时输出增益时才写 `联合(SE+AGC)` |
| 联合(SE+AGC) | 增强与响度/增益控制联合优化 | 本领域的稀有个案（如 SE-AGCNet），务必核实其控制对象是否真是增益 |
| 非AGC(相邻：…) | 严格不是 AGC（修复、超分、声码器、编解码） | **收录时必须注明理由**；冒号后写具体相邻领域 |

**降噪不等于增益控制。** 一条记录若只输出抑制掩码、不改变输出电平，控制对象只能写
`降噪掩码`，不得因"听起来变清楚了"就记成增益控制。反过来，若某工作明确联合优化两者
（输出既降噪又归一到目标 LUFS），写 `联合(SE+AGC)` 并在正文写明联合方式。
属于相邻领域但被收录的（如生成式修复、带宽扩展），必须在控制对象列写
`非AGC(相邻：修复·超分)` 并在正文给出收录理由——大型档存在的意义是回答
"用生成式做增益/修复值不值"，不是选型池。

## 规模分档

按**量化前、含编码器**的参数量划分。边界值**左闭右开**：30M 归中型，500M 归大型。

| 档 | 参数量 | 说明 |
|---|---|---|
| 经典 DSP 档 | `n/a(非神经)` | 反馈环 / 测量算法，**本领域的实际主力**；集中见 `01-classical-dsp.md` |
| 小型 Small | < 30M | 轻量神经网络降噪与增益 |
| 中型 Medium | 30M–500M | **预期稀疏，不得为凑数灌水**（Task 4 判定） |
| 大型 Large | > 500M | 生成式修复；**必须同时记 NFE 或 RTF，否则不得入表** |

口径说明（四条，写数时必须遵守）：

1. **含编码器 / 解码器**：声码器类组件（如 BigVGAN）参数量要写完整生成器，
   并在"版本/形态"列注明 `声码器（非 AGC）`。
2. **量化前为准**：INT8 / INT4 后的体积与实测 MCPS 写进 `edge` 列或正文，
   不改写 `参数量(M)`。
3. 无神经参数量的一律写 `n/a(非神经)`，且"版本/形态"列必须含
   `经典 DSP` 或 `标准/测量算法`（校验器规则 `non-neural-form` 强制，
   防止"没有参数量"变成逃避核实的口子）。
4. **参数量对扩散 / 流匹配类失效**：多数值 < 500M，但推理成本由采样步数决定。
   大型档记录必须同时给出 **NFE（函数评估次数）** 或 **RTF**，缺一不可入表
   （Global Constraint 4）。NFE/RTF 写在"指标"列，参数量仍照实写。

## 编号化自测口径

**AGC 大量组件没有公开基准数据集**（WebRTC AGC2、SpeexDSP、ffmpeg `loudnorm`
都没有 VoiceBank-DEMAND 那样的榜单）。处理方式不是免检，而是**定义编号化的自测口径**：

- `基准` 列写 `自测(no public benchmark)`；
- `指标` 列**必须**引用某个编号（如 `收敛时间 0.8s (自测口径 1)`），
  由校验器规则 `selftest-ref` 强制；
- 同一口径下的数字才可横向比较；**不同口径的数字不许直接比**，跨档对比时必须在正文明说。

### 自测口径 1：稳态远场语音

| 项 | 值 |
|---|---|
| 场景 | 远场（1–3 m）稳态说话语音，考察常规增益收敛能力 |
| 输入电平范围 | -40 ~ -20 dBFS（扫三段：-40 / -30 / -20 dBFS 各一次） |
| 噪声类型与 SNR | 稳态空调/风扇类粉噪，SNR 10 dB；另跑一遍无噪纯净版作上限参照 |
| 目标响度 | **-24 LKFS**（GY/T 282-2014 §4.3；ATSC A/85:2013 §6 同为 -24 LKFS/LKFS） |
| 容差 | ±2 LU（GY/T 282-2014 §4.4；A/85 为 ±2 dB） |
| 真峰值上限 | -2 dBTP（GY/T 282-2014 §4.6） |
| 收敛判据 | 起播后短时响度（3 s 窗）首次进入目标 ±1 LU，且**连续 3 s 不越界** |
| 测量窗口 | 起播后 10 s：前 2 s 计收敛段，后 8 s 计稳态段 |
| 报告量 | 收敛时间、稳态误差（后 8 s 短时响度标准差）、增益波动（LU 峰峰值）、削波率、PESQ、STOI、SI-SDR、DNSMOS |

### 自测口径 2：电平突变（过冲与增益泵浦）

| 项 | 值 |
|---|---|
| 场景 | 说话人由远走近 / 突然提高音量，考察闭环的过冲与抽动 |
| 输入电平范围 | -35 dBFS 稳态 5 s → **突跳至 -10 dBFS** 5 s → 回落 -35 dBFS 5 s；阶跃在 20 ms 内完成 |
| 噪声类型与 SNR | 无外加噪声（SNR 视为 ∞）；**另跑一遍**叠加 SNR 15 dB 稳态噪声 |
| 目标响度 | **-24 LKFS**，容差 ±2 LU（同口径 1） |
| 收敛判据 | 每次阶跃后 **2 s 内**短时响度回到目标 ±1 LU |
| 测量窗口 | 15 s（含两次阶跃） |
| 报告量 | 过冲 dB、下冲 dB、增益泵浦次数（短时响度穿越目标 ±1 LU 的次数）、恢复时间、削波率 |

### 自测口径 3：低电平噪声底（噪声提升与静音段行为）

| 项 | 值 |
|---|---|
| 场景 | 无人说话、只有环境底噪（常驻采集的绝大多数时间），考察 AGC 是否把噪声底抬起来 |
| 输入电平范围 | -55 dBFS 稳态粉噪；**子条件 B** 再加 -45 dBFS 微弱语音 |
| 噪声类型与 SNR | 粉噪（比白噪更接近室内底噪）；子条件 B 语音相对噪声约 +10 dB |
| 目标响度 | 语音段 -24 LKFS ±2 LU（同口径 1）；**纯噪声段不应被抬到目标值** |
| 噪声段判据 | 纯噪声段输出响度应 **≤ -34 LKFS**（即低于目标 ≥10 LU）；> 该值判为噪声提升失败。⚠️ **此判据为本调研自定义的工程约定，无标准出处**——标准只规定节目响度目标，不规定静音段行为，实测时须在正文标注这是自定阈值 |
| 收敛判据 | 20 s 内短时响度稳定、无持续爬升：最后 5 s 内短时响度变化 < 0.5 LU |
| 测量窗口 | 20 s |
| 报告量 | 噪声提升量 dB、噪声段输出响度 LUFS、语音段 SI-SDR、削波率、增益上限是否被触及 |

### 响度目标值的标准出处（逐条查证，不许编）

| 标准 / 文档 | 目标响度 | 容差 | 真峰值上限 | 适用范围 | 出处与状态 |
|---|---|---|---|---|---|
| **ITU-R BS.1770-4** | 不规定目标值，只定义 **LUFS / LKFS 与真峰值测量算法**（K 加权 + 400 ms 块、绝对门 -70 LUFS、相对门 -10 LU） | — | — | 测量算法本体 | ITU-R BS.1770-4（2015-10）。⚠️ **ITU 官网版本表显示 -4 已被 BS.1770-5（2023-11）取代（In force）**；本调研以 -4 为基准（计划指定），引用时须注明现行版本为 -5 |
| **EBU R128** | **-23.0 LUFS** | **±0.5 LU**（直播 ±1.0 LU） | **-1 dBTP**（制作环节线性音频） | 欧洲广播 | [EBU R 128（2014 修订）PDF](https://tech.ebu.ch/docs/r/r128-2014.pdf) 第 h)/i)/m) 条。⚠️ 冲突：EBU 官网 loudness 页写 "-23 LUFS ±0.2 LU"，与 R128 正文 ±0.5 LU 不一致——**按 R128 正文取 ±0.5 LU** |
| **ATSC A/85:2013** | **-24 LKFS**（无元数据交付/交换场景） | ±2 dB | 低于 **-2 dBTP** | 北美数字电视 | [ATSC A/85:2013 with Corrigendum No.1](https://www.atsc.org/a85-2013-with-corrigendum-no-1/) §6。⚠️ 第三方站点提及存在更新版 "A/85:2026-07"，**未在 ATSC 官网核实，不作为依据** |
| **GY/T 282-2014**（中国） | **-24 LKFS** | **±2 LU** | **-2 dBTP** | 中国数字电视节目制作 / 播出 / 分发 | 《数字电视节目平均响度和真峰值音频电平技术要求》§4.3 / §4.4 / §4.6（国家新闻出版广电总局，2014-12-03 发布实施，现行）；修改采用 ITU-R BS.1864:2010（MOD） |
| **GY/T 377-2023**（中国） | **-15 LKFS 或 -24 LKFS**（可双版本分发） | ±2 LU | **-1 dBTP** | 中国网络视听节目（非直播，直播参考执行） | 《网络视听节目音频响度技术要求和测量方法》§5.1 a)/c)。-15 LKFS 适用于嘈杂环境（车载 / 户外 / 公交地铁），-24 LKFS 适用于安静环境 |
| **GY/T 262-2012**（中国） | 测量算法（IDT ITU-R BS.1770-2:2011） | — | — | 被 GY/T 282-2014、GY/T 377-2023 规范性引用 | 《节目响度和真峰值音频电平测量算法》。⚠️ 注意它对齐的是 **BS.1770-2**，不是 -4/-5 |
| **GY/T 379-2023**（中国） | 不设目标值，只规定监测规程 | — | — | 数字电视节目音频响度监测 | 《数字电视节目音频响度监测规程》 |
| AES TD1004.1.15-10 | **-16 ~ -20 LKFS** | — | — | 流媒体 / 网络文件播放 | ⚠️ **二手引用**：经 ITU-R BS.2434（2018）报告转引，未直接读到 AES 原文；仅作参考，不作广播法定目标 |

**查证结论（重要）**：

1. **计划 Task 1 Step 2 示例骨架里的 `-16 LUFS`（标注"需核实目标值出处"）查无广播电视/网络视听标准出处。** 它只落在 AES TD1004 的 -16~-20 LKFS 区间里（且是二手引用）。
   因此**不采用 -16 LUFS 作为默认自测目标**，默认目标取 **-24 LKFS ±2 LU**（GY/T 282-2014 + ATSC A/85 一致，且是中国的现行行业标准）。
2. **中国的对应标准存在且已核实编号**：GY/T 282-2014（广播电视，目标 -24 LKFS）与
   GY/T 377-2023（网络视听，目标 -15 或 -24 LKFS）。laos 属于"网络视听/终端录音"侧，
   引用时以 **GY/T 282-2014** 为主引用，GY/T 377-2023 仅作嘈杂环境备选（裁定理由见下）。
   **裁定 1（主引用标准）**：以 **GY/T 282-2014（-24 LKFS ±2 LU / -2 dBTP）为主引用**，
   GY/T 377-2023 仅作嘈杂环境备选。三条理由：

   （a）**-24 LKFS 是国内外一致的基线**——GY/T 282-2014 与 ATSC A/85:2013 同为该值，
       且 GY/T 377-2023 也把 -24 列为安静环境选项；取 -24 可同时落在两个标准内。
   （b）**laos 的音频只喂给 ASR 与情绪蒸馏，不用于外放收听**，因此应优先保留动态范围。
       GY/T 377-2023 的 -15 LKFS 是为"车载 / 户外 / 公交地铁等嘈杂环境听得清"设计的
       压缩取向，会牺牲语音动态，对下游识别无益。
   （c）**-2 dBTP 比 GY/T 377-2023 的 -1 dBTP 多留 1 dB 真峰值余量**，
       对电平不可预测的常驻采集场景更安全。

   沿用第 3 条的前提：两者都是**成品节目**标准，采集端无标准，此处是外推而非标准规定。
3. **未找到**：中国是否有专门针对"终端语音采集 / 录音 App"的响度目标值标准——
   GY/T 系列检索到的只有电视节目与网络视听节目两类**成品节目**标准，
   **没有面向采集端的响度目标**。因此自测口径的目标是"让采集结果符合成品节目标准"，
   这是本调研的合理外推，须在正文写明是外推而非标准规定。
4. **未核实**：EBU R128 现行版本号（EBU 官网称 v5.0，本次读到的是 2014 修订 PDF）；
   ATSC A/85 是否有 2026 年新版。两者均不影响目标值 -23 / -24 的取值。

## 指标

每个指标值**后面必须跟基准名或自测口径编号**，不写裸数字（通用规则 `metric` 强制）。

- **闭环指标**（经典 DSP 档的主要语言）：收敛时间、稳态误差、增益波动（LU 峰峰值）、
  过冲 / 下冲 dB、增益泵浦次数、削波率、噪声提升量 dB
- **感知指标**（有参考信号时）：PESQ、STOI、SI-SDR
- **无参考指标**（真实录音）：DNSMOS
- **工程指标**：RTF、MCPS、NFE（扩散 / 流匹配步数）、内存、模型体积 MB、功耗 mW

写法示例：`收敛时间 0.8s、稳态误差 0.4dB (自测口径 1)`、
`PESQ 2.87 (VoiceBank-DEMAND)`、`NFE 30 / RTF 0.8 (RTX 3090, 自测口径 1)`。

**不同基准或不同自测口径的数字不许直接比。** 跨档对比时必须同基准；若做不到，
在正文明说"不同基准，不可直接比较"。

## 记录 schema（12 列，列名逐字照抄）

## 跨切标记

### `edge`（端侧可部署）

| 值 | 含义 |
|---|---|
| `yes: <runtime+量化>` | 有公开转换案例或官方端侧导出路径；必须带 runtime 名与量化方式，例：`yes: TFLite Micro INT8`、`yes: 任意 CPU（C 定点实现）` |
| `no` | 需要服务端 GPU，或算力/显存明显超出端侧 |
| `unknown(未找到公开转换案例)` | 没有证据，不等于不行——这是合法值，不算 TBD |

runtime 覆盖：TFLite / TFLite Micro、ONNX Runtime Mobile、CoreML、NCNN、MNN、RKNN、
QNN（Qualcomm AI Engine Direct，与 laos 现状直接相关）、CMSIS-NN / Ethos-U（MCU 侧）。

**沿用 SER 04 的 A/B 两档**（引用，不重算）：

- **A 档·真端侧**：原生 App / aDSP / Sensing Hub / 手机 NPU，可拿到 mW 级低功耗档；
- **B 档·proot 内**：通用 Linux CPU 推理，**空闲功耗 400–1000 mW 量级**（拿不到 aDSP 的 mW 档）。

laos 现状是 B 档，且**第三方 App 拿不到 aDSP**（内核 fastrpc 对未授信进程 attach audioPD
返回 -EACCES，见 SER 04）。因此经典 DSP 条目虽可写 `yes: 任意 CPU（C 定点实现）`，
但**仍只能跑在 AP 上**，备注里必须说明这一点——"能跑"不等于拿到了低功耗档。

## 红线（三条，本目录所有文件通用）

1. **二次增益红线。** 在"采集后"层加闭环增益前，必须先确认固件 / TX-path 是否已做过增益
   （`01-classical-dsp.md` 的核心问题）。**该结论出来前，任何"采集后"条目都不得被当作
   落地推荐写进 `07-adoption.md`**，只能作为能力记录。
2. **降噪不得混记为增益控制。** 控制对象列只写该组件真正控制的量；
   只有输出掩码的写 `降噪掩码`。这一条由规则 `control-target` 与人眼共同把关。
3. **生成式修复不得进入会产生记忆的链路。** 生成式方法会"补出"输入中不存在的语音内容，
   在"原音频即焚 + 只留文本/情绪记忆"的架构下，补出的内容会进入转写与情绪判定，
   形成**无来源的记忆**。大型档只作边界论证，不作选型池（见 `04-large-models.md` 与
   `07-adoption.md`）。
