## 1. 一句话结论

文章可证的部分只有三样：**一个 Skill（LitReview）规定了五步流程**、**一段可直接复用的提示词**、**一份 11 篇文献的成品展示**。真正值得学的是它展示出的质量差异——**综述的价值不在「每篇讲了什么」，而在「论文之间接不接得上」**：方法能力后面要接复杂环境下的失效，模型压缩后面要接真机端到端延迟，比较数字后面要交代硬件与数据条件。

⚠️ 但「20 分钟」「投稿级」都是引流口径：文章没有给文献清单、检索式、参考文献，也没有给 Skill 本体；11 篇对一篇综述偏少。**它能交付的是「可打磨的初稿骨架」，不是可投稿稿。**

| 项 | 文章口径 |
|---|---|
| 工具 | WorkBuddy + 文献综述 Skill `LitReview` ✅ |
| 选题 | 音频分类与识别 ✅ |
| 成品标题 | 《音频分类与识别研究进展：2023—2026》✅ |
| 文献量 | 11 篇代表性论文（7 篇会议 + 4 篇期刊）✅ |
| 检索截止 | 2026-10-15 ✅ |
| 成品结构 | 摘要、关键词、正文、参考文献齐全；正文含研究范围、方法分类、研究对比（第 7 节）、后续方向（第 8 节）、局限说明 ✅ |
| 耗时 | 「20 分钟」🔶（未给计时方式，未复现） |
| 质量定性 | 「接近投稿标准」「有了继续打磨的基础」🔶（作者判断） |

### 2.2 LitReview 规定了什么（✅）

文章原话可归纳为五步：

1. 确定主题和范围；
2. 查找、筛选和阅读论文；
3. 比较不同研究；
4. 完成正文；
5. 交付**完整综述 + 参考文献**。

并明确一条交付底线：**「不能只给一份目录或几张表格就算完成」** ✅。

### 2.3 文章给的提示词（✅ 原文）

```text
请使用 lit-review，围绕【研究主题】完成一篇文献综述，重点回答【核心问题】，文献范围为【时间范围】。
按照 Skill 的流程查找、筛选和阅读文献。按研究问题或方法类别组织正文，不要逐篇拼接摘要。
交付完整综述和参考文献。没有拿到全文、没有核实的内容，请明确说明。
```

三段分别锁定三件事：**范围/核心问题**、**组织方式（禁逐篇拼接）**、**交付与诚实边界（未核实必须标注）**。

## 3. 文章展示的六个质量经验（逐条附依据）

### 3.1 综述的主线是「论文之间的对话」，不是逐篇摘要

文章重点检查的不是文笔，而是**衔接**：前文介绍「用文字描述识别声音」的方法，后文紧接着讨论「背景声混进来后识别效果如何」——「前一项工作展示了方法的能力，后一项补充了它在复杂环境下的问题」✅。

⚠️ 这是全篇最值钱的一条。判断一段综述是否成立，只需问：**这一段里的两篇论文，为什么必须放在一起？** 答不出来，就是摘要拼接。

### 3.2 比较数字必须带实验条件

文章注意到：单模型与多模型联合给出的分数被**分开讨论**；训练时间在不同显卡上测得，**不能直接算成同一硬件下的加速效果** ✅。

⚠️ 这条应升级为硬规则：任何跨论文数字，必须同时记录**数据集 / 指标 / 硬件 / 训练或推理配置**；缺条件就不进对比表，只做定性描述。

### 3.3 对比表是阅读入口，不是附录

第 7 节的研究对比表把「代表论文、主要思路、优势、限制」放在一起；文章建议**先看表再读章节**，尤其适合刚接触方向的人 ✅。

⚠️ 表的正确用法是「先给地图，再给细节」；表本身也是查重灾区——每行必须能回指到正文的一个论证段，否则就是装饰。

### 3.4 后续方向要从局限里长出来

文章举了两条：模型压缩之后追问「放到具体设备上，算上采集、特征处理和等待输出，还能不能满足实际需求」；背景声影响识别之后追问「不同背景、多个声音重叠时是否稳定」✅。

⚠️ 可检验标准：**每条 future work 都必须能追溯到某篇论文的某个局限**；凭空设想的方向一律删。

### 3.5 交付物定义决定质量下限

Skill 明确要求完整综述 + 参考文献，不接受目录或表格充数 ✅。

⚠️ 这与工程里的「Definition of Done」同构：**交付物清单写不清，模型就会用最便宜的产物交差。**

### 3.6 AI 稿的定位是「可打磨的初稿」

文章自己给了投稿前的五步：聚焦主题、补齐关键文献；回原文核对方法/结果/引用；把重点章节写充分；突出相比已有综述多解释了什么；按目标期刊调整篇幅、图表与参考文献格式 ✅。

⚠️ 这五步没有一步能由「20 分钟生成」替代；它们才是从初稿到投稿的真实成本。

## 4. 可复用 SOP：九步综述工作流

> 用法：这是把文章的五步展开成可验收的九步；适用于用户自己的论文综述、组会汇报底稿，也可作为将来 skill 的流程骨架。

| 步 | 名称 | 输入 | 动作 | 产出 | 验收 |
|---|---|---|---|---|---|
| S0 | 范围合同 | 主题、核心问题、时间窗、目标读者/期刊 | 写清纳入/排除标准与交付格式 | 半页 scope 说明 | 能用一句话回答「这篇综述不写什么」 |
| S1 | 检索 | 关键词、同义词、 venue 列表 | 多库检索，记录检索式与日期；去重 | 检索日志 + 候选池 | 检索式可被他人复现 |
| S2 | 筛选 | 候选池 | 标题/摘要粗筛 → 全文细筛；每条记纳入或排除理由 | 纳入清单（建议 20–50 篇） | 排除理由不是「感觉不相关」 |
| S3 | 结构化精读 | 纳入清单 | 每篇固定字段：问题/方法/数据/指标/条件/局限/与谁对话 | 单篇卡片 | 每张卡片都有「局限」与「关联论文」 |
| S4 | 综合矩阵 | 单篇卡片 | 按方法族聚类；填「代表论文/主要思路/优势/限制/实验条件」 | 对比矩阵 | 每个数字都带条件；每族 ≥2 篇 |
| S5 | 叙事大纲 | 对比矩阵 | 按问题或方法分节；每节先写「为什么这几篇放一起」 | 带论证句的大纲 | 不存在「一篇一段」的流水账 |
| S6 | 写作 | 大纲 + 矩阵 | 先成文对比表，再写正文；能力段后接失效/边界段 | 完整初稿 | 每节都有承接句与转折句 |
| S7 | 溯源核验 | 初稿 | 逐条回原文核对方法、结果、引用；区分全文与摘要 | 核验记录 | 未核实内容显式标注，不混入事实层 |
| S8 | 差异化与适配 | 初稿 + 已有综述 | 写「本文比已有综述多解释了什么」；按期刊调格式 | 投稿候选稿 | 差异声明可被审稿人检验 |

**与文章五步的映射**：文章的「确定主题和范围」= S0–S2；「查找、筛选和阅读」= S1–S3；「比较不同研究」= S4–S5；「完成正文」= S6；「完整综述 + 参考文献」= S6–S7。文章没展开但真实存在的两步是 **S7 溯源核验** 与 **S8 差异化声明**——也正是 AI 初稿最容易被审稿人击穿的地方。

### 4.1 每节必须回答的三个问题（写作时贴在屏幕上）

1. **这一节在回答哪个研究问题？**
2. **这两篇论文为什么必须放在一起？**（能力 → 失效 / 方法 → 代价 / 结论 → 反例）
3. **读者读完这一节，能带走哪一句判断？**

### 4.2 对比表的五列（最小可用）

| 方法族 | 代表论文 | 主要思路 | 优势 | 限制（含实验条件） |
|---|---|---|---|---|

⚠️ 文章的表是四列（代表论文/主要思路/优势/限制）；本文加「方法族」作为第一列，否则表格会退化成论文清单。

## 5. 增强版提示词（在文章模板上补三处）

```text
请使用 lit-review，围绕【研究主题】完成一篇文献综述，重点回答【核心问题】，文献范围为【时间范围】，
目标期刊/读者为【目标】。

按以下流程执行，并为每一步留下可核查的记录：
1) 先写 scope：纳入/排除标准、检索式、检索日期；
2) 检索并筛选，给出纳入清单与排除理由；
3) 每篇按固定字段精读：问题/方法/数据/指标/实验条件/局限/与哪些论文对话；
4) 先产出方法族对比矩阵（含实验条件列），再按研究问题或方法类别组织正文；
5) 每节必须说明「为什么这些论文放在一起」，禁止逐篇拼接摘要；
6) 每条 future work 必须追溯到某篇论文的局限；
7) 交付完整综述 + 参考文献；所有数字标注数据集/指标/硬件条件；
8) 没有拿到全文、没有核实的内容，单独列「未核实清单」，不得混入正文事实。
```

⚠️ 增强点只有三个：**过程留痕**（S1–S3 可核查）、**条件随数字走**（S4/S6）、**未核实隔离**（S7）。其余保持文章原意。

## 6. 交付验收清单（可直接勾）

- [ ] scope 能一句话说清「不写什么」
- [ ] 检索式、库、日期齐全，他人可复现
- [ ] 纳入文献 ≥20 篇（低于 11 篇不足以支撑「研究进展」）
- [ ] 每篇有「局限」与「关联论文」字段
- [ ] 对比表每行能回指正文一个论证段
- [ ] 每个跨论文数字都带数据集/指标/硬件条件
- [ ] 不存在整段「一篇论文一段摘要」的结构
- [ ] 每条 future work 可追溯到具体局限
- [ ] 参考文献逐条可打开、可核对
- [ ] 未核实内容集中在独立清单，正文不混用
- [ ] 有「相比已有综述多解释了什么」的差异声明

## 7. 与 laos 现有纪律的对照

| 文章经验 | laos 既有做法 | 关系 |
|---|---|---|
| 「没有拿到全文、没有核实的内容，请明确说明」 | 来源诚实纪律（被墙则重构并声明）；数字一律实测，不引用宣称值 | ✅ 同构，可直接复用 |
| 比较数字要交代实验条件 | 复现隔离区「论文数字不作断言，自己跑的才记；跑不动的等比缩距并写明」 | ✅ 同构且更硬 |
| 交付完整综述 + 参考文献 | 调研文档「已落地/推荐/不做」三态记账 | ◐ 目标不同：前者是学术综述，后者是工程采纳 |
| 对比表先给地图 | `docs/research/INDEX.md` 的「按问题找文档」导航 | ✅ 同构：先地图后细节 |
| 后续方向从局限里长出来 | 调研文档的「不做也写清理由」 | ✅ 同构：边界即路线图 |

⚠️ 本仓的 19,792 篇论文语料是**会议元数据 + 主题切片**，不是全文库；`papers/` 只有 115 篇 PDF。它可以支撑 S1 的候选发现，**不能替代 S2–S3 的全文精读**，更不能拿来做「全量综述」的证据。

⚠️ 文章没有给 Skill 本体，以下是按本仓习惯推的最小骨架；真要实施，按 `docs/superpowers/plans/` 体例另写计划，不在本文冒充。

skills/lit-review/

三条硬边界（写进 SKILL.md，不靠提示词自觉）：

1. **无全文不进事实层**：只有摘要的文献，结论必须标「摘要口径」。
2. **无条件的数字不进对比表**：缺数据集/指标/硬件任一项，降级为定性描述。
3. **future work 无出处即删**：每条必须挂到某篇论文的局限。

## 9. 诚实的边界（本文档自身的前提）

- **单一来源且是引流文**：文末「后台私信回复【B859】免费领取」表明这是 Skill 推广；文章展示的是精选成品，不是随机样本。
- **关键证据缺失**：没有 11 篇文献清单、没有检索式、没有参考文献、没有 Skill 本体；「20 分钟」「投稿级」无法验证。
- **截图不可读**：快照中对比表与第 8 节配图是占位 SVG，未能读到实际表格内容，因此本文**不评价该表的真实质量**。
- **11 篇偏少**：对「2023—2026 音频分类与识别研究进展」这种跨度，11 篇只能算骨架；文章自己也承认要「补齐关键文献」。
- **立场偏差**：作者在卖 Skill，天然强调「接近投稿标准」；本文把「可交付初稿」与「可投稿稿」明确分开，是对该立场的校正。
