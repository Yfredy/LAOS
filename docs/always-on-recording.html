05隐私合规 checklist + 风险矩阵

最低合规集合（一页 checklist）

  • 可见指示：录音中必须有系统级可见信号（LED / 常驻通知 / 状态栏），且不可被软件关闭
  • 显式触发：默认不常录；常开需用户显式开启且可随时一键停止
  • 全局禁录开关：等价 laos 的 LAOS_REC=0
  • 默认短期留存 + 自动删除：用户期待自动删除（UCB 实证），行业默认却是永久存储——最大的认知错位
  • 分级留存：原始即焚、文本长留、向量中留
  • 审计可回放：每次录音调用（无论成败）可查（laosctl mic）
  • 旁观者（bystander）策略：录音里有不在场的第三方说话人是常态，不确定归属就不打标签
  • 中国法域单独同意：声纹属敏感个人信息；不建声纹库

风险矩阵

家庭 / 个人自录低风险

同意链最短，但仍需可见指示与自动删除。laos 的默认场景。

会议 / 课堂录音中风险

需在开始时明确告知；多说话人归属错误率高（DIHARD III 真实域 DER 35–45%）。

公共场所常开高风险

旁观者无法给予同意；Friend 吊坠即因此被公众反噬。

看护场景（被看护人无法同意）高风险 · 建议放弃

同意能力缺失，持续录音难有合法基础。

职场 / 员工监测高风险

权力不对等使"同意"无效，多法域明确限制。

秘密录音 / 隐蔽采集禁止

无指示 = 直接违反最低合规集合第一条，也是所有争议事件的共同点。

法律查证（中国民法典 1033 条 / PIPL / GDPR / 美国两方同意州）与社会接受度实证见 social-acceptance.md。

07对 laos 的反向映射

已做对、且业界稀缺（差异化卖点）

  • 内核级能力阶梯 mic.listen → mic.record → mic.transcribe → mic.always_on（高层含低层、默认收紧）——开源世界里没有第二家把录音做成受内核闸门管控的系统资源
  • 6 小时即焚 + 每次调用写审计 + LAOS_REC=0 全局禁录——同时命中 UCB 实证与最低合规集合三条
  • 驱动加载不启动录音线程，录音只能被显式 syscall 拉起——规避 Recall 式"默认开启"的死法
  • 端到端零云：本地 VAD → 本地 SenseVoice → 本地记忆
  • 听觉产物直接进入 Agent 消费层（journal / diary / mood_report），业界只有时间线或检索问答，laos 是三合一

可以抄（落到具体模块）

laos 模块抄谁抄什么
laos/vad.pySilero VAD / WebRTC VAD保持零依赖自研兜底，提供"外接 ONNX VAD"适配点（30 ms chunk <1 ms CPU 是硬指标）

建议路线：3 个月内能落地的 3 件事

  1. 能力阶梯 + 状态指示落地到真机控制面（MIC_CAP_LEVELS / mic_state / laosctl mic + Android 常驻通知）——唯一同时解决合规、接受度与调试问题的动作。
  2. 存储与调度：Opus + 配额 FIFO + 占空比档位（rec.start(encoding=) / LAOS_REC_MAX_BYTES / mic.always_on_start(duty=)），把"24/7"从口号变成可测量的 %/天。
  3. 蒸馏只加一件：ear.stream（LocalAgreement）+ 情感改纵向差分；diarization 与声学事件标为实验特性，等 NPU 通路打通再上。

必须先做的一次架构选择：继续 proot → 常驻成本数百 mW，mic.always_on 在手机上不成立；进 mW 档必须做原生 App 走 aDSP / Sensing Hub。
